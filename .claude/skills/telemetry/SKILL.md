# /analyze-telemetry [--source auto|mirror|editor|player|<路径>] [--module <模块>] [--last N]

日志行格式、字段、事件清单的**契约在 [`docs/telemetry.md`](../../../docs/telemetry.md)**，
本文件只管「拿到日志之后怎么查」。

分工只有一句：**脚本负责算，你负责推理。**
`analyze.py` 把几万行压成 200 行以内的结构化摘要，你从摘要里提假设，再定向回读原始片段去验证。

> **禁止把原始日志整份读进上下文。** 不许用 Read / cat / grep 打开 `Editor.log`、`Player.log`
> （本机实测 632 MB，一份能顶掉整个上下文，而且会把真正的线索冲淡）。
> 要看细节只有一条路：`analyze.py query`，按 **会话 + 序号窗口**取。

---

## 0. 定位日志源（不能跳）

```bash
python .claude/skills/telemetry/analyze.py sources
```

`--source` 默认 `auto`，顺序是 **镜像目录 → 指针文件 → 显式路径 → 猜默认路径**
（契约见 `docs/telemetry.md`「分析脚本的定位顺序」一节）。

**编辑器下优先吃镜像目录 `Logs/telemetry/<sid>.log`（一段会话一个文件）。** `Editor.log` 是
本机全局的：别的 Unity 工程同时开着，它的每帧日志能把本工程刚写的埋点整段挤出去（实测三次，
30 秒后尾部 256 MB 一条不剩，20 分钟后整份文件被换掉）。镜像是工程内独占的那一份，还天然分好段。
目录里有 `.log` 就**默认吃整个目录** —— 多段会话一起分析，「成功会话 vs 失败会话 diff」
「同一个错误跨几段会话」才成立；`--last N` 数的始终是**会话段**，不是文件数。
显式指定用 `--source mirror`。

跨文件的会话先后**优先用 `session_start` 的 `at`**（墙钟时刻），旧文件缺这个字段才回退文件
mtime；摘要头部「会话排序」那行写明用了哪种，兜底时带 ⚠（mtime 会被拷贝 / 同步 / 备份改掉）。

镜像目录不可用（还没在编辑器里跑过 / 目录里只剩报告 md）才退到指针文件
`Logs/telemetry-source.txt`（运行时写的「本工程日志在哪」），指针也不可用才猜默认路径 ——
**猜出来的路径会校验第一条 `session_start` 的 `prod` 跟本工程对不对得上，对不上直接报错退出**，
不会拿着别的工程的日志往下分析。显式给 `--source <路径>` 只警告不中断（你可能就是想看别的
工程）；镜像与指针来源不校验（本来就是本工程写的）；日志里没有 `session_start`（老日志）不算
校验失败。`sources` 会列出镜像目录概况、指针状态、各候选源的来源与身份校验结果；摘要头部也
注明这次用了哪条。拿不准先跑 `sources`。

| 情况 | 怎么办 |
| --- | --- |
| 镜像目录不存在 | 还没在**编辑器**里跑过游戏（镜像只在编辑器下写）。跑一次就有；只看出包的日志就 `--source player`。 |
| 一条埋点行都没有 | `summarize` 扫空尾窗会自动 ×4 扩大重扫到全量再下结论，不用手动加 `--tail-mb`；仍然没有就按摘要列的可能逐个排：别的工程的日志 / 本工程没跑过。**别硬分析没有数据的日志。** |
| 报「工程身份校验未通过」直接退出 | 猜出来的路径读到的不是本工程日志。去 Unity 里跑一次游戏生成指针文件后用默认 `--source auto`；确实要看别的工程就显式 `--source <路径>`。 |
| 没有 `Player.log` | 要出过包并运行过才有。只想看编辑器就 `--source editor`。 |
| 文件读不到 / 没权限 | 脚本给的是人话提示，照着做（关编辑器 / 复制一份出来指路径）。 |

## 1. 拿摘要

```bash
python .claude/skills/telemetry/analyze.py summarize --source editor [--module core.asset] [--last 3]
```

| 参数 | 说明 |
| --- | --- |
| `--source` | 默认 `auto`（镜像目录→指针→显式→猜）/ `mirror`（镜像目录，整个目录一起吃）/ `editor` / `editor-prev` / `player` / `player-prev` / 完整路径或目录 |
| `--last N` | 只看最近 N **段会话**（默认 3）。**绝不跨会话找因果**，脚本已按 `sid` 切好；镜像目录下跨文件按会话先后取，不是「最近 N 个文件」 |
| `--module` | 只筛这个模块的错误与慢操作排行；上下文事件序列仍保留全部（否则前序就没意义） |
| `--tail-mb` | **只对单文件大日志生效**（`Editor.log` / `Player.log`），镜像文件每份整读、不受它影响。只读尾部多少 MB（默认 64，0 = 全量）；扫空（或没扫到 `core/session_start`）会自动 ×4 扩大重扫直到全量，stderr 有进度提示 |
| `--pre` / `--top` / `--max-lines` | 前序条数 / 排行条数 / 摘要行数上限 |

摘要的七节怎么读：

- **会话清单** —— 先看「结束方式」。`未见 session_end` = 崩了或还在跑；`日志截断` = 开头缺 `session_start`，那段的序号不连续是正常的。
- **错误聚类** —— 按堆栈指纹归并。`来源` 是 `埋点` 还是 `原生`（Unity 自己写的报错，没走 bridge）。**原生的往往更早**，埋点起来之前的错看这里。
- **错误前序** ★ —— 多次出现的**共同前缀**，根因第一嫌疑人。但它只是**相关**，见第 2 步。
- **成功／失败对照** —— 同一流程走通与出错的事件序列 diff，`-` 是成功独有、`+` 是失败独有。
- **状态流转移矩阵** —— 「有 enter 无 exit」里，会话结束时停留的那个状态属正常，**中途**的才是异常终止。
- **慢操作排行 / 性能尖峰** —— 带前后各 3 条事件与帧号，看是哪个操作把帧顶上去的。

## 2. 提 2～3 个根因假设（不多不少）

只提摘要**支持得住**的。每个假设必须能写成这三件套：

```
假设：core.asset/load_failed 的 key=SampleScene_Game 在 Addressables 组里没登记
预测：如果成立，失败会话里这个 key 从来没成功 load 过（一次都没有），且成功会话走的是另一个 key
证伪：query 回读成功会话的 core.asset/load，只要看到同一个 key 成功过，这个假设就死了
```

**一个假设都提不出来就明说**，不要硬凑 —— 见第 4 步。

## 3. 用 query 定向回读，验证或证伪

```bash
python .claude/skills/telemetry/analyze.py query --source editor \
    --session <sid> --around <序号 s> --window 30
```

| 参数 | 用途 |
| --- | --- |
| `--session` + `--around` + `--window` | 主力用法：看某次错误前后发生了什么（窗口按会话内序号 `s` 算） |
| `--module` / `--event` / `--level` | 把某一类事件在会话里的全部出现拉出来（比如「这个 key 到底成功过没有」） |
| `--grep <正则>` | 对整行原始文本匹配，**非埋点行靠它捞**（原生异常、Shader 报错） |
| `--limit` | 输出上限，默认 120 行。撞到上限说明条件太宽，收窄，别调大 |

镜像目录下 `--session <sid>` 先去同名的 `<sid>.log` 取窗口（不翻整个目录），命中不到才扫其余
文件；输出按文件分段打印，`--limit` 是**跨文件的总预算**。

一轮下来还定不了，就换假设再来一轮。**别把窗口越开越大去凑答案** —— 那等于变相整份读日志。

## 4. 相关 ≠ 因果（这一节是这个工作流的命门）

错误前序里的共同前缀是**时序相关**，不是因果。会误导的三种常见情况：

- 前序里那条事件只是「必经之路」（每次启动都走，成功也走）→ 拿成功会话对照一眼就穿帮。
- 真正的根因**根本没埋点**，前序里看到的是它的下游。
- 事件被限流丢过（摘要会标 `触发限流 N 次`）→ 序号断层不代表没发生。

所以每条根因结论都必须带**置信度**和**验证方法**：怎么复现、改什么能让它变好或变坏。
只有时序相关就写「相关，未证实」，别升格成根因。

## 5. 证据不足时，明说查不出来

**这是最有价值的输出之一，比硬猜一个根因强。** 格式：

```
查不出来。缺的数据：失败发生在 GameState.OnEnter 里，但那段只有进入和失败两条埋点，
中间三个分支（配置校验 / 资源预热 / UI 预创建）走了哪条，日志里没有。
该补：Assets/_Project/Scripts/Core/Flow/GameState.cs 的三个 return false 分支各补一条 TrackError，
把判定用到的数值写进 p（docs/telemetry.md 第 2.2 节「失败比成功值钱」）。
补完跑 /instrument-module <模块>，复现一次再来分析。
```

尺子照 `docs/telemetry.md` 第 2.2 节那四类：意图入口 / 状态迁移 / 失败分支 / 长耗时操作。
指到**具体文件 + 具体位置**，别写「建议加强埋点」这种废话。

## 6. 报告（固定格式，落 `Logs/telemetry/<时间戳>.md`）

文件名 `Logs/telemetry/YYYYMMDD-HHMMSS.md`。`Logs/` 已 gitignore，**只写这一个目录，不写工程别处**。
镜像的 `<sid>.log` 也在这个目录里，互不干扰 —— 分析脚本只认 `.log`，报告不会被当成日志读。

```markdown
# 埋点分析 20260916-0130
源: Editor.log 尾部 64 MB ｜ 会话 3 段（aaaa1111 / bbbb2222 / cccc3333）

## 现象
bbbb2222 进 GameState 后场景没加载出来，日志停在 t=6.1s，没有 session_end。

## 证据
1. `core.asset/load_failed` ×2，key=SampleScene_Game —— sid=bbbb2222 s=8 / s=12
2. 同一 key 在 aaaa1111 s=8 成功（`core.asset/scene_load` ms=290）—— 说明地址本身是通的
3. 两次失败的共同前序止于 `core.flow/state_enter`（TitleState→GameState）

## 根因（置信度：中）
…一句话说清。证据链哪一环是推断、哪一环是实证，要分开写。

## 验证方法
怎么复现；改什么能证伪（「把 X 改成 Y，如果还失败就不是这个原因」）。

## 建议改法
改哪个文件的哪一段，为什么。**这里只写建议，不动手。**
```

证据**一律带 `sid` + 序号 `s`**，让人能用同一条 query 复现。
**不要引用行号**（尾部扫描起算、文件还在增长，行号不稳），也别把本机绝对路径写进报告。

## 7. 只诊断，不改代码

这个工作流的产出是**一份报告**。改动走 `/dev`（或 `/new-feature` 的实现步），埋点补全走 `/instrument-module <模块>`。
在这里改 `.cs` 就失去了「诊断是独立一环」的意义 —— 改完再复现一次，才知道改对没有。

## 已知限制（写报告时要诚实）

- **原生日志没有级别标记**：`Debug.LogError("字符串")` 和 `Debug.Log` 在 `Editor.log` 里长得一模一样，脚本只认得出异常 / 编译错误 / Shader 错误 / 断言四类。普通的错误日志只能靠 `core.log/unity_error` 埋点 —— 这也是那条埋点存在的理由。
- **尾窗只对单文件大日志**：`summarize` 读 `Editor.log` / `Player.log` 时扫到 0 条埋点（或扫不到 `core/session_start`）按 ×4 自动重扫到全量，摘要头部注明实际范围与是否回退过；`sources` 为保持秒级不做重扫，只标「未扫全量，用 `--tail-mb 0` 确认」。镜像文件每份整读，没有这一层。
- **缺 `at` 的会话排序不保证可靠**：旧镜像文件与埋点上线前的日志没有 `at`，只能按文件 mtime 兜底排先后，而 mtime 会被拷贝 / 同步 / 备份改掉。摘要头部会标；写报告时凡是依赖「A 会话在 B 之前」的结论，先确认那一行没有 ⚠。
- **镜像只有编辑器下才有**：真机 / 出包那条路一个字没变（`Player.log` / logcat 是进程独占的）。运行时只保留最近 20 个会话文件，更早的已被清理 —— 要看更早的只能去 `Editor.log` 碰运气。
- **一次运行同一个错误可能出现两遍**（Unity 原生一份 + 埋点转一份），脚本按指纹归并，归并是启发式的；来源显示 `埋点+原生` 就是归并过的。
- **Android 不在这里**：logcat 不落文件，用 `adb logcat -s Unity` 自己抓，抓下来存成文件再 `--source <路径>`。

## 完成标准

摘要拿到了、假设提过了、用 query 验证或证伪过了、报告按第 6 节格式落到 `Logs/telemetry/`，
并在对话里给出结论一句话 + 下一步（改哪、补哪个埋点、还是需要开发者先复现）。
或者明确停在「查不出来 + 缺什么数据 + 该补哪个埋点」，**这也算完成**。
