# /refine-prd — PRP 阶段 1：PRD 精炼

特性名：**$1**　需求：$2

把模糊需求问清、收敛成结构化 PRD，作为后续 PRP 的输入。产物 `PRP/$1/prd.md`。

## 步骤

1. 读 `CLAUDE.md` 与相关模块的 `ai-docs/docs/modules/<模块>/<模块>-module-guide.md`（存在才读），了解现状与约束。工程是空骨架时，如实写「本特性是该模块的第一次落地」。
2. 对需求中**不明确处主动提问**，合并成一次提问：玩法边界、手感 / 数值预期、失败条件、要不要联机 / 存档、哪些留给后续。关键决策由用户拍板，**不臆断**。
3. 产出 PRD，写入 `PRP/$1/prd.md`：

```markdown
# PRD: <特性名>

## 问题 / 动机
为什么做，玩家侧解决什么。

## 目标（可度量）
- G1 ...
- G2 ...

## 范围 / 非目标
- 做：...
- 不做：...

## 玩家故事 / 关键场景
- 作为玩家，我 X 时会 Y，从而 Z。

## 验收标准
- [ ] 可观测、可验证的条件（能写成 EditMode 测试的优先写成断言式描述）

## 涉及模块 / 依赖
`Assets/_Project/Scripts/Runtime/<Module>/` 里哪些模块；要不要新建模块 / asmdef；
要不要新的 ScriptableObject 配置、新场景或新预制体；外部包依赖。

## 待确认问题
- Q: ...
```

4. 列出未决问题，等用户确认后再进入 `/generate-prp $1`。

## 原则

- PRD 只描述「要什么」，不写实现方案（那是 PRP 的事），更不写具体类名 / 字段名。
- 涉及新建模块时，在「涉及模块」里先按 `CLAUDE.md` 的目录约定给出模块名（`Game.<Module>`），方便 PRP 阶段定位文档与规则。
- 简单 / 中等任务不必走 PRP，用 `/dev` 或 `/new-feature` 即可。
