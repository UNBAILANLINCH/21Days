# PRD: 调查界面（线索卷宗 · 文书翻阅 · 推理连线的三块面板）

> 状态：草稿（2026-10-07），待 `/generate-prp`。
> 本 PRD 覆盖「玩家收集线索与文书 → 翻阅核对 → 连线推出结论 → 结论影响推进」的界面闭环。
> **范围收窄说明**：按 2026-10-07 的决定，本次只定「要什么」（用途、玩家故事、验收标准），**数据形状留待策划答 `design/features-spotlight/00_功能总览.md:379`（§8.1 第 1 条「阶段一用哪套设计」）之后补**。因此本 PRD 的「涉及模块」与「待确认问题」两节刻意留白，不做实现承诺。
> 术语：本文的「文书」指游戏内可翻阅的官府 / 寺观账册类道具（归业簿、赈粮册、名簿、香火册等）；「线索」指玩家调查得到的可归类、可引用的信息条目。两者关系见待确认 Q1。

## 问题 / 动机

- 聚光灯的明线是一条**文书链**：名簿 → 归业簿 → 赈粮册 → 香火册，每一份都「对不上」或「空」，阶段七一次揭开「一个人『成为』了粮」（`design/features-spotlight/12_调查与线索.md:116` R7）。这条链现在**在工程里没有任何承载体**：背包面板只有一个「线索」筛选，没有分类、没有翻阅、没有比对（`design/features-spotlight/13_系统界面清单.md:107,108,109` 三行现状列全写「无」）。
- 结果是**玩家拿到了线索却看不见自己拿到了什么**，更做不出「对不上」这个判断——而叙事的落点恰恰是「玩家亲手把这几处连起来」（`12_调查与线索.md:117` R7 末尾 [推断]，`:152` §6）。
- 旧版策划稿 `docs/design/features/10_疑案调查与信息.md` 曾把这件事定义为「纸上备忘 / 镜中档案」两个界面，该稿已随旧版冻结（`docs/roadmap.md:261`），其界面形态按判据并入本条（`docs/planning/旧G组-新目标映射与遗留资产.md` 第 2.8 节）。

## 目标（可度量）

- G1 **看得见**：玩家获得线索 / 文书后，能在面板里找到它，并知道它是**什么时候、从谁那里**得到的。当前已收集条数与获得顺序可见。
- G2 **归得类**：线索可按**章节**与**人物**两个维度归类浏览（`12_调查与线索.md:119` R10 原文「按章节 / 人物分类」）；同一份文书既在「已持有道具」里、也能在「可翻阅」里找到（`:121` R12 [推断]）。
- G3 **翻得动**：四种点名的文书（归业簿、赈粮册、名簿、香火册）可翻页阅读，含竖排文字（`:115` R6、`:154` §6）；翻到哪一页在本次打开期间保持。
- G4 **连得起**：能把若干线索卡摆到一起并建立关联，形成一条玩家自己搭的推理；关联可撤销、可重来。
- G5 **有产出**：推理得出结论后，结论**必须落成一个可被其它系统读到的事实**（推进阶段 / 解锁对话 / 解锁地点三者之一或组合，具体用途见 Q4）。没有产出的推理等于装饰，不允许。
- G6 **不剧透**：界面只呈现玩家已经掌握的信息，不提示「哪条重要」「还差几条」；不做完成度百分比（对应设计约束「不做强引导」，`docs/design/features/00_功能总览.md:185`）。
- G7 **不卡流程**：任何一块面板都不是必经关卡；玩家不打开也能推进到结局（对应旧版 [10] 的「走、看、问、照拿信息，拼成判断再推进」，`docs/design/features/10_疑案调查与信息.md:1`）。

## 范围 / 非目标

- **做**：三块面板（线索卷宗 / 文书翻阅 / 推理连线）的用途与相互关系；面板的打开入口与关闭规则；新线索的获得反馈（右上角浮字与「新线索解锁」提示，`:120` R11）；推理结论的输出契约；空状态与无内容时的表现。
- **不做**：
  - 不定义线索与文书的数据字段、表结构、存储分区（等 §8.1 第 1 条答复后随 `/generate-prp` 定）。
  - 不做玩家手写备忘（判据 A9：新目标未提，不作首版功能）。
  - 不做线索的**自动**关联 / 自动结论（与 G6「不剧透」冲突）。
  - 不做「线索收集度」成就、图鉴、奖励。
  - 不改背包与道具本身的分类规则（归聚光灯 [05] 皮面具与道具，`13_系统界面清单.md:107`）。
  - 不做文书的世界内阅读（拿到手才能翻，不做场景里的碑文 / 匾额即时阅读）。
  - 小地图 / 地图导航不在此（`13_系统界面清单.md:110` #18 归别处）。

## 玩家故事 / 关键场景

- 作为玩家，我在官府案卷处翻到赈粮册，看到同一个名字领了两次粮——我想把这条和之前名簿上的记录摆在一起。
- 作为玩家，我打开线索面板，能按「这一段查到的人」把线索过一遍，而不是在一长串里瞎找。
- 作为玩家，我把两条线索连起来，系统认下了我的判断，随后某个原本不开口的人愿意跟我说话了。
- 作为玩家，我拿不准自己连得对不对，能拆掉重连，不用怕连错就废档。
- 作为玩家，我漏看了一份文书也没关系，照样能往下走，只是少知道一点。

## 验收标准

每条都要机器可判（测试断言）或肉眼可验（回放里看得见）。

- [ ] A1 **获得即入库**：通过与 NPC 对话、拾取、翻阅三种来源各获得一条线索后，线索面板里三条都在，且各自的来源与顺序正确（回放：`Dialogue` / `Inventory` / `Narrative` 三个模块各受本次改动影响——对话给出线索、背包持有文书、剧情记录结论）。
- [ ] A2 **双维归类**：同一批线索按章节筛选与按人物筛选，结果集与预期一致；切换筛选不丢选中项（EditMode）。
- [ ] A3 **文书可翻页**：四类文书各翻到末页再返回，页码与内容一致；竖排文本不出现截断或乱序（回放 + 肉眼）。
- [ ] A4 **打开状态保持**：翻开某份文书到第 N 页，关闭面板再打开，仍停在第 N 页（EditMode）。
- [ ] A5 **连线可撤销**：建立关联后撤销，关联数回到建立前；重开面板不残留上次未确认的连线（EditMode）。
- [ ] A6 **结论有产出**：推出一条结论后，其它系统能读到该结论（用一条剧情条件验证：结论成立前某对白选项不可用、成立后可用）（回放：`Narrative` 与 `Dialogue`）。
- [ ] A7 **不剧透**：面板内不出现「重要」「推荐」「完成度 N%」这类字样；未获得的线索不占位、不显示为「???」（回放截图肉眼核对）。
- [ ] A8 **不卡流程**：三块面板全部不打开的情况下，从某阶段入口能一路推进到下一个阶段（回放）。
- [ ] A9 **获得反馈**：新线索到手时右上角浮字出现且不打断操作；连读获得多条时提示合并、不刷屏（回放）。
- [ ] A10 **空状态**：一条线索都没有时打开面板，显示空状态而非报错或空白（EditMode）。
- [ ] A11 **输入完整**：三块面板都能用键盘与手柄完整操作（打开 / 切换 / 翻页 / 关闭 / 返回），Esc 走通用关闭（沿用 `docs/roadmap.md:298` H3）。

## 涉及模块 / 依赖

- **框架层已有可直接用**：UI 四层栈与面板（`Panel` 层、`OpenAsync` / `CloseAsync` / `CloseTopAsync`、默认选中、Esc 路由、沉浸模式隐藏）、存档分区服务（本功能需要新分区或并入现有分区，待定）、通知服务（右上角浮字）、世界暂停（面板打开时是否暂停待定，见 Q5）。
- **内容侧已有**：对话系统已能承载「身份决定对话内容」（条件选项 + 条件事实）；任务系统有 `Counter` 目标可用于计数类门槛；背包已能区分「线索」类道具。
- **缺口（本 PRD 不解决，随 `/generate-prp` 定）**：线索的持久结构与归类维度、文书的页结构、推理关联与结论的存储形状、结论如何成为剧情可读的事实。**这四项都依赖 §8.1 第 1 条（阶段一用 sp02 附身对话路线还是 sp03 文书路线），故本 PRD 不预设形状。**
- **与旧版的关系**：`docs/design/features/10_疑案调查与信息.md` 已冻结，其「两个界面」形态由本条取代；不新开第二份真源。

## 待确认问题（列出，不预设默认值）

- Q1 **线索与文书是不是一套东西**：文书本身也是道具、也要能当线索卡进推理面板（`:121` R12 是 [推断]）。是「文书 = 一种线索」，还是两套结构互相引用？影响归类维度与检索方式。
- Q2 **推理的判定强度**：玩家连线是**自由关联**（自己看着办，系统只存不判），还是**有正确解**（连对了才算推出）？若后者，连错的后果原文未写（`:136` 末行 [待定]），要不要做失败反馈？
- Q3 **结论的用途**：推进阶段 / 解锁对话 / 解锁地点，三者中原文只写「推动什么」未写清（`:119` R10 末 [待定]）。结论是**可消耗**（用掉即消失）还是**常驻事实**？
- Q4 **是否暂停世界**：面板打开时冻结世界（与任务面板一致，`docs/roadmap.md:320`）还是继续走时间？影响「边躲追兵边翻文书」这类场景。
- Q5 **推理面板的形态**：卡片连线（原文「连线组合」，`:119` R10）在 PC 上是用鼠标拖拽、还是键盘选取配对？这决定验收 A11 的具体可达性。
- Q6 **衣肆推理与面板的关系**：sp02 衣肆那段「逐个附身顾客、找出取衣服的人」（`:114` R5）是**场景内的推理小玩法**，不是面板。两者是否共用同一套「关联 → 结论」机制，还是各做各的？
- Q7 **文书未获得时能否预览**：拿到前在面板里是否完全不可见（倾向是，与 G6 一致，但需确认）。
- Q8 **阶段一的线索来源**：sp02 路线靠附身对话、sp03 路线靠市令交互与文书（`:110` R1、`:113` R4）。两条路线下线索的获得方式不同，界面是否要做两套入口？（**本问题的答案取决于 §8.1 第 1 条**。）

## 排除在外的既有结论（避免重复讨论）

- 不做玩家手写备忘（判据 `旧G组-新目标映射与遗留资产.md` A9）。
- 不做「不做强引导」之外的重要性提示（同上，且 `docs/design/features/00_功能总览.md:185` 为功能层硬约束）。
- 「账簿」在聚光灯里指**玩家用过的身份记录**、超量触发追逐（`12_调查与线索.md:123` R14），与本 PRD 的账册类**文书**同名不同物，命名需隔离。
