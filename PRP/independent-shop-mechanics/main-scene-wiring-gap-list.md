## 3 你提到的四项分别怎么接

### 身份使用

最小通路：现场人物稳定ID → 既有RequestControl → 控制变更 → 同一份IdentityState → 当前职业操作权限 → 行为结果。

- 已有的是人物角色字符串和TryEnter/TryExit，借入会记账；不是每个身份动作都已经写账或投射到正式剧情事实。
- 有效身份与实际控制人物必须一致。身份到期、死亡、禁用和回本体需统一收权；“已借过”不能代替“当前生效”。
- 正式档恢复不应靠ControlChanged重新TryEnter来重建状态，否则可能刷新时限或再次记借用账。
- 露馅纯规则已存在，但当前未见运行时ResolveExposure调用，Installer也未注入后果策略。**完整六种露馅/追逐/死亡不是本次五店独立试玩已确认范围**；若本期要演身份暴露，需单独明确所用信号与后果，不能将它宣传为已接好。
- 剥皮、残血、材料消耗、记忆和后期面具等未定内容不自动加成五店门槛。

### 奖励与提交

最小通路：规则接受完成 → 记录该次完成及交付标识 → 写正式物品/事实 → 通知 → 请求稳定保存。

| 地点 | 当前成果 | 必补接线 | 尚需内容决定 |
| --- | --- | --- | --- |
| 戏班 | Theater.Completed | 演奏完成持久记录；成功一次消费 | 是否给物品/线索；没有确认前只记完成，不编奖励 |
| 衣肆 | Clothing.Received | 衣物进正式背包，领取与发放一致 | 衣物物品ID/数量；现成唯一答案是否为本期正式答案 |
| 金银行 | Keys、Ornaments、Submitted | 金钥匙/首饰真实产物，首饰提交扣除、钥匙保留；材料与局部额度一致 | 物品ID；材料是局部额度还是实际库存；提交后的额外奖励 |
| 客栈 | 占位对白结束提示 | 线索/已读记录与可回看入口 | 正式线索、是否有任务或物品结果 |
| 酒肆 | tavernCompleted、BOSS禁用；示例剧情已有击败flag | 正式击败标记、退场恢复；若有奖励则一次结算 | 胜利奖品、失败恢复/重试口径、正式剧情节点 |

不新增跨店门票：衣服、钥匙暂不成为其它独立玩法的强制条件。身份失败和动作失败都应显示可理解的原因，不能只静默return。

### 战斗结果

当前已经有：酒客身份门槛 → sample_boss_battle → 既有BattleFlow/BattleArena → 对应Generation的结果消费。

当前示例数据的链条是Victory → cleared → End的Success，失败为Downed → retreat → End的Downed。因此店铺读Success并非简单的结果键拼错；它读的是叙事终局，不能不看表就机械改成Victory。

| 结果/异常 | 本次应完成的处理 |
| --- | --- |
| 胜利 | 一次写击败结果、按确认内容交奖、BOSS退场、恢复原世界并保存；继续游戏仍保持退场 |
| Downed | 不交胜利奖；反馈失败；按确认口径恢复玩家和可挑战状态。当前只给提示，不等于正式死亡/重试规则齐备 |
| 开场被拒或加载失败 | 撤待开战/待结果状态，释放世界锁、输入与面板，允许正常重试 |
| 中途取消或结果未被叙事接受 | 不标胜利、不交奖；恢复现场及可重试状态。不能一直等不到NarrativeChanged而残留待结果标记 |
| 旧战斗结果/新局/读档切换 | 核对Generation及目标/阶段归属，旧结果不影响新的店铺会话 |

Exposed、BossPhaseChanged等是既有叙事能力，不是此酒肆示例已声明的分支。只有正式酒肆设计要求使用时才补相应配置，不平白扩大本次范围。

## 4 最容易漏的保存和返回

1. **角色保存不等于玩法保存。** 遭遇快照有当前控制和角色状态，但不会自动保存衣服领取、打造额度、戏班完成及酒肆本地标记。
2. **存档分区存在不等于被捕获。** IdentitySaveData已有类型，当前运行时未见IdentityRules.Capture/Restore的生命周期调用；必须把活状态写进去、读回来。
3. **有自动保存不等于有定时可继续快照。** SaveTriggerBridge已有任务、开箱、对白、叙事和场景事件触发；GameSession.Tick只处理已请求保存。ReplayRecorder的周期快照是回放系统，不能当作玩家存档功能已满足。用户此前提出的定时快照/关键节点/手动保存三项应分别验收。
4. **保存时机和保存内容要同时补。** 请求领衣节点保存，却没有持久Received和物品，会得到能落盘但不能正确恢复的档。未完成打造要明确保存完整预留状态或拒绝保存，不能只存Available。
5. **显隐不是重置。** 退出店铺只收表现；酒肆离区清醉酒是专属规则，不能泛化为五店每次离区Reset。
6. **新局不是重新绑场景就够。** Controller与ShopPlaytestState是根作用域单例；需在会话开始重置/恢复，避免新存档继承上一局成果。
7. **正式地图替换也算接线验收。** 保留角色ID、入口引用和交互对象；重新核对碰撞、道路、活动区及相机，不需要重建规则。
