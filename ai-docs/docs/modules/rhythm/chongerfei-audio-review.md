# 虫儿飞中段检视与独立测试包检查点

本次针对当前 `ChongErFei.asset` 的 56 个 Tap 检视。音频片段仍为原文件 16–56 秒，谱面 schemaVersion=2、chartOffsetMs=0；没有改曲谱、音频或个人输入补偿。本报告是工程/信号证据，尚无实际听感验收。

## 时刻口径

本文“片段时刻”是歌曲时间轴，不含开始前的 3 秒倒数；“原音频时刻”=片段时刻+16 秒。
谱面 timeMs、chartOffsetMs、用户输入补偿和视觉偏移不能混用。自动跟拍校准仍播放单独生成的 120 BPM 参考点击，不以这首伴奏中的不均匀起音当校准真值。

## 实际检视

使用 Windows 自带媒体解码器将项目 MP3 离线解码为 48kHz PCM；全文件解码时长 162.997 秒。截取指定 40 秒，计算 40–220Hz、220–2500Hz、2500–12000Hz 和宽频的正向谱变化候选。分析窗 21.33ms、步长 5ms，候选之间至少 80ms；这不是 1ms 测量，也不能把谱变化峰直接等同于某一乐器的实际起音。

中段约 11.52–30.74 秒（原音频 27.52–46.74 秒）中，大多数宽频候选在旧目标之前约 4–14ms，22580ms 附近约为 +1ms。这种小幅共同差值没有显示某一局部明显漂移，可能包含分析窗、取峰方式或解码起点因素，不足以证明整谱应整体提前。

## 优化顺序

1. 完成当前玩家入口的场景回归与独立包存档隔离；入口和 Hold 尾部反馈已补齐，Player 仍待构建验证。
2. 实际试听上述候选并对齐同一音乐声部，再做局部目标修改，记录 ID、旧新时间与依据；不把输入补偿当谱面修正。
3. 分步校准向导：独立视觉反馈、听声跟拍及组合确认，清楚说明采样数、预热、偏差符号和质量拒绝；不声称分离出硬件物理延迟。
4. 制谱工具路线：先选明确外部格式（例如手工制作 osu!mania 再转换 .osu），验证毫秒记录、Tap/Hold、BPM 元数据和资源引用；不先造泛化导入框架。
5. 视觉可读性和设置：更明显的轨道边界、Hold 头/尾与完成反馈，预览速度/显示设置；输入侧保留会话隔离、同域批次水位与真正迟到诊断，补设备变化和 Player 焦点回归。
