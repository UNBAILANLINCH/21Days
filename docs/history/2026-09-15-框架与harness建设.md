## 一、这两天做出了什么

从一个 2D URP 空模板开始，两天内落地了四样东西。

**框架层 `Game.Core`**，十二个子系统，全部经依赖注入注册、按固定顺序串行启动：
启动与服务生命周期、状态流（含场景加载基类）、UI 四层分层与面板栈、音频、
Addressables 资源、Luban 配置表、JSON 存档、输入、定时器与时钟、对象池、日志、平台隔离。
分五个波次做，每波都过 code-reviewer 审查并逐波交付审核。

**玩法层一个端到端样板 `Sample`**：配置表 → 纯 C# 规则算价 → 意图对象 → 状态加载场景 →
面板显示 → 返回标题，把框架每一层都串起来跑通一遍。新模块照它的形状写。

**Claude Code harness 五层**：能力层（技能与 Unity MCP）、知识层（`ai-docs/` 与模块三件套）、
策略层（硬规则、按 glob 注入的规则、钩子、数据驱动 lint）、编排层（`/dev` 与 PRP 四阶段）、
进化层（`/learn`、`/gc`、静态不变量、行为 eval）。

**四类角色各有入口文档**：程序看开发手册，策划看 `designer-guide`，美术看 `artist-guide`，
第一次拉工程的人跑 `/onboard`。README 顶部有角色导航表。

## 二、关键取舍与理由

完整的设计理由在 [`architecture.md`](../architecture.md)，这里只记**当时为什么这么选**、以及后来被实测修正的部分。

| 取舍 | 当时的理由 | 后来发生了什么 |
| --- | --- | --- |
| 管线一律用公开方案，不抄参考工程的私有实现 | 参考工程的配置表、资源封装、Lua 桥接都是公司内部定制，团队维护不起 | 保持。选型全部落在 UniTask / VContainer / MessagePipe / Addressables / Luban / LitMotion 等 |
| 不引入一体化框架（TEngine、GameFramework、QFramework） | 它们自带整套分层与约定，会和本工程的 asmdef 分层与 harness 规则打架 | 保持 |
| 纯 C#，不做 Lua 双语言 | 单一技术栈，模块可替换性靠 asmdef 边界而不是语言边界 | 保持。热更真需要时优先看 HybridCLR，不换语言 |
| 玩法模块经 `GameplayInstaller` 注册进**根作用域** | 原计划用玩法场景的子作用域，实测行不通：状态由 `GameFlow` 从根解析，且标题界面时玩法场景还没加载 | **方案改了**，顺带绕开了「VContainer 会清空新建的 `*LifetimeScope.cs`」那个坑 |
| 中文字体接**全局 fallback**，不改默认字体 | 原计划改 TMP 的 Default Font Asset | **方案改了**：预制体上的组件把原字体的 guid 显式序列化了，默认字体是查找链最后一环，改它不生效 |
| Android Release 只勾 ARM64 单架构 | 双架构会把 IL2CPP 原生产物打两份，体积近翻倍 | 保持。要兼容 32 位老设备改一行即可，位置在 `BuildScript.cs` 注释里 |

## 三、harness 的四条纪律

第二天深读了一套成熟 harness（75 技能 / 21 钩子 / 28 规则）的代码与它的总纲文档，
落地了四条纪律。**最值钱的不是它建了什么，是它诚实记录了什么烂掉了**——
18 个钩子最后只剩 1 个还在硬拦，知识读取埋点采了五个月八千多条而报告目录至今不存在，
一套评估烧了约九百万 token、首轮问题七周后被原样再抓一遍。

1. **载体锚定**：新增任何会自己跑起来的东西，必须写明执行载体（且必须是**已被证明在运转**的机制）、
   5 秒可证伪的状态锚点、退场条件。给不出载体就显式标注，不假装会被记得。细则见
   [`.claude/rules/harness-authoring.md`](../../.claude/rules/harness-authoring.md)。
2. **强制机制的成本在解锁链路，不在拦不拦得住**。解锁靠状态推断必死，靠人打一条确定命令才活。
   本工程的模块文档闸就踩过这个：原本只认 Read 工具的读取记录，用 `cat` 读完仍被拦，当天修掉。
3. **钩子注入写第三人称事实陈述**，不写第二人称祈使句——祈使会触发提示注入防御。
   细则见 [`.claude/rules/hook-injection-style.md`](../../.claude/rules/hook-injection-style.md)。
4. **subagent 自报完成不算完成**，主窗口自己复跑再采信。这条上线当天抓到三次真问题。

## 四、刻意没做的（重点，别重新提议）

| 没做 | 为什么 | 什么情况下再议 |
| --- | --- | --- |
| 知识读取埋点与聚合统计 | 参考工程那边就是烂的：数据采了五个月，聚合报告从没被任何决策消费过 | 文档超过百篇、且真有人会读报告时 |
| 知识适应度自动评估 | 单次全量约九百万 token，且产出的报告无人消费 | 模块数上两位数之后 |
| 知识注入中央库 | 参考工程已冻结，他们自己的诚实测试显示 32 条信号里 0 条需要那个形态 | 不再议，`/learn` 直接改源头文档就是正确答案 |
| 技能查重钩子、组件注册表、技能发布流程 | 那是 75 个技能规模才需要的治理手段，本工程十几个 | 技能过五十个时 |
| PRP 物理闸门（文件系统级锁） | 多人高频场景才需要，本工程靠 `/review-change` 人工审足够 | 团队扩大且 PRP 高频时 |
| 网络层、热更、FMOD | 单机游戏，本期不需要 | 玩法定了之后按需 |
| GitHub Actions CI（整条） | **2026-09-16 已删除**：三个 secret 配齐后仍卡在 Unity 账号激活 **401**——Personal 许可证绑机器，CI 每跑一次都是新机器，绕这限制要在线登录账号，链断在 Unity 侧，**不是密钥没配**。除激活外所有环节都验证通过 | 先有一个不开 2FA 的专用 Unity 账号，或升 Pro 用 Licensing Server；根因与重做步骤见 [`ci-setup.md`](../ci-setup.md) |

**单机但留了联网的缝**：服务全部是接口且经容器注入、时间只来自 `IClock`、玩法规则是纯 C# 类、
状态改变走意图对象、存档是带版本的 DTO。将来要做联网，换实现即可，玩法代码不动。
详见 [`architecture.md`](../architecture.md) 第 7 节。

## 五、已知缺口

**Android 包不能上架**。`-Release` 开关解决了 64 位这一条，但 Google Play 要求新应用交 AAB 格式
而不是 APK，正式签名也还没配（现在用的是 Unity 调试密钥，只能自己装着测）。

**PRP 四阶段从没真跑过**。命令齐备、三道门已落进流程，但整套形态还没在真需求上验证过。
建议在第一个真玩法模块上完整跑一次再决定留不留——没跑过就废弃，和跑完觉得太重而简化，是两件事。

**行为 eval 测不到模块文档那道闸**。产出落在临时目录，钩子的路径匹配不命中。
边界写在 `pitfalls.md` 里，没假装覆盖全了。
