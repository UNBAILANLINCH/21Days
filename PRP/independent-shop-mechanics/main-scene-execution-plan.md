# 五店主场景玩法接线执行文档

日期：2026-10-13。状态：用户已批准并开始主场景实施；五店预摆与接线已写入正常Boot/SampleScene，验证结果与剩余限制见[实施范围与记录](main-implementation-scope.md)。本文保留空间组织与执行约定，历史能力盘点不是最新完成度。

> 后续工作区已有主场景接线源码增量。当前哪些已写、哪些尚未安装或验收，以[接线缺口与交付清单](main-scene-wiring-gap-list.md)的核查快照为准；本文保留空间组织与执行约定，不用旧状态段落判定最新完成度。

五店是同一张现有主地图上的玩法地点。按用户2026-10-13截图的空间口径，先在当前3D灰盒街面后方预摆五个Cube店铺建筑；人物使用截图中现成的小人素材和既有2.5D表现，名称用TMP。柜台、道具和操作点预摆在街面或建筑门口。借身份与切换控制在原场景进行，各店玩法可以分别体验，不要求串成五店主线。

店铺人物按Hierarchy分组，进入对应店铺活动区才显示该组人物及局部操作表现。这里的“进入”是同图靠近店前活动区，不是加载室内。后续五个店铺3D资产和正式地图到位后替换外观或重绑场景引用，保留已接好的玩法规则。

之前将“玩法独立实现”理解为“另建独立启动场景、四个房间和独立战斗舞台”是错误方向。原方案不再作为接线依据；已有纯规则可以保留，错误的场景壳和移动接管必须在实施阶段撤除。

## 一 执行边界

| 项目 | 本次做法 |
| --- | --- |
| 地图 | 以截图所示的现有3D灰盒主场景为过渡底图，保留现有地面、道路、镜头与控制；本次不另造试玩地图或店内场景。后续允许替换正式地图与建筑资产 |
| 五店位置 | 原关卡图从左到右为戏班、衣肆、金银行、客栈、酒肆；截图后方五处标记代表五个建筑占位。世界坐标、尺寸和通行间距在编辑器核对，不能从截图像素直接确定 |
| 占位 | 五个店铺建筑先用3D Cube；人物复用现成小人素材/预制体，不能用Cube演员或新2D试玩舞台替代。柜台、物品可用Cube，人物与物品用TMP标名字；编辑器制成预制体并预摆 |
| 分组显隐 | 每店一个Hierarchy组，建筑保持街面可见，进入该店活动区才显示其人物、名字、提示和局部操作物；公共角色和当前控制人物另行保留可见。具体状态边界见下一节 |

| 十二阶段 | 本次不加跨店主线前置，不把衣服、钥匙自动当作酒肆强制门票 |

**过渡场景的表现已由截图指定，具体场景文件仍需核对。** 当前源码的新游戏/继续路径是Boot→MonsterEncounterState→地址IsometricEncounter，源码说明该地址指向SampleScene。实施时沿正常Boot定位截图中的3D灰盒场景，在其上接五店，不再自行创建独立地图；默认地址不能当作最终美术地图已确定的证据。

### 店铺Hierarchy与显示规则

“层级”按场景Hierarchy分组落实；本轮不新增五套Unity Layer、相机或场景加载。以下是作者预摆结构示意，不要求建立新的通用框架：

```text
MainScene（现有3D灰盒）
  ExistingWorld / ExistingPlayer / ExistingCamera / ExistingHUD
  Shops
    Theater / Clothing / Forging / Inn / Tavern（五个店铺根节点）
      BuildingVisual（当前Cube，后续替换店铺3D资产）
      BuildingCollision（随建筑尺寸核对）
      ActivityArea（店前进入/离开范围，持续有效）
      InteractionPoints（持续保留的入口位置与引用）
      Actors（现成小人预制体，稳定ID与职业登记）
        ActorRoot（角色逻辑、位置和身份保持有效）
          Visual（小人、TMP名称、局部提示，按规则显隐）
      LocalProps（预摆柜台/操作物及其显示引用）
```

| 情况 | 显示与交互 | 状态处理 |
| --- | --- | --- |
| 尚未进入任何店铺 | 五个建筑可见；公共人物与当前控制人物可见；其它店铺人物和局部提示隐藏 | 保留各角色身份、位置、领取/打造/醉酒等数据，不销毁、不重新生成 |
| 当前控制人物进入某店活动区 | 显示该店人物和局部操作表现，启用该店局部交互；退出其它店铺局部界面并隐藏其非控制人物 | 使用当前实际控制人物的逻辑位置判定，不能一直测停留的本体；不触发新场景加载 |
| 离开店铺 | 关闭该店局部界面，隐藏该店非控制人物及提示；建筑仍可见 | 不清已领取成果或重置角色；酒肆醉酒按其既有离区规则清理，不能与通用隐藏混成全店重置 |
| 店铺人物正被控制并走出活动区 | 该人物及控制标记保持可见、可移动；不因所属店铺隐藏而被强制切回本体 | 仍由唯一控制归属与现有移动驱动推进；改控后按位置与所属店铺重新计算其显示 |
| 区域边界重叠 | 在有效范围内保留当前店；离开后优先选择所在范围中最近的入口，距离相同按固定店铺顺序 | 只更新一次活动店状态，设置进入/离开缓冲避免边缘闪烁；不每帧重置玩法 |
| 对白、音游、战斗及返回/读档 | 沿已有暂停、世界锁与返回流程恢复；重新按当前位置和控制对象计算显示与交互 | 显隐不是保存进度真源；返回不得重建人物或覆盖醉酒/领取快照 |

**不能直接对整店根节点或ActorRoot调用SetActive(false)。** 现有TamingActor.OnDisable会发出不可用事件，EncounterSceneView据此同步角色可用性；这会影响切人，不能把不可见等同于不可控制。首版只切已缓存的角色/道具Renderer、名字与局部提示的显示，隐藏人物不参与普通交互焦点与点击选人；店前入口范围始终保留。隐藏的操作物也要同步关闭其专用交互/点击检测，建筑和公共道路碰撞保留，避免不可见操作物挡路。是否保留人物实体碰撞沿现有角色规则，不因隐藏随意改动。

现有巡逻、路线切换、醉酒和控制规则先保持一致推进；需要这些状态的角色不能因隐藏停止规则。只含表现的动画或特效可在确认不承载玩法事件后暂停。Hierarchy分组本身没有性能收益；减少Renderer显示可降低人物绘制负担，但预摆资产仍在内存、既有逻辑仍运行。首版对比全显与按店显隐的CPU/GPU时间、绘制批次及内存，再决定是否需要进一步优化，不能提前承诺明显提升。显示引用在初始化缓存，进入/离开或控制变更时更新，不每帧遍历全场景查找组件。

**替换美术的边界：** 替换BuildingVisual的Cube为正式店铺3D模型，重新核对尺寸、碰撞和门前操作点；不删除角色稳定ID、职业映射、活动区和玩法引用。若正式场景整体替换，将这些预制体按同一角色ID重新摆放并绑定既有入口，相机投影和道路可走性重新验收；不把外观替换当成重写五店玩法的理由。

## 三 五店玩家操作和接线

### 戏班

1. 玩家在戏班门口/街面借学徒，完成进入戏班活动区的身份核验。
2. 在原场景找到都知并切到都知，和指定巡逻学徒交互，将其切到第二条作者预摆路线。
3. 切到乐正，走到原场景的音乐解谜操作点，打开现有下落音游。
4. 达标交付完成结果；低分、主动退出或技术中断返回原主场景，可再尝试。当前控制与位置按活动前状态保留，不跳标题、不回新出生房间。

**接线项：** 学徒/都知/乐正稳定ID与身份映射；核验点；目标巡逻者的两条路线；音乐操作点；真实控制权限适配；演奏结果消费。
改路线由既有角色规则执行，不能另一个店铺脚本每帧拖巡逻者Transform；仅换路线不能顺带重置生命、驯服归属或复活角色。

**验收：** 地图与相机不替换；错误身份无法开演奏；巡逻者确实沿另一条路走；控制乐正后真实输入能打完现有谱面；成功/失败/退出都能在原街面继续操作。

### 衣肆

1. 玩家走近顾客甲、乙、丙，在原场景分别切人并与顾客/裁衣匠交互，取得证词。
2. 已取得证词可以回看。玩家选择自己认为是取衣人的身份，再向裁衣匠上报。
3. 错误身份明确拒绝；正确身份领取一次衣服，并提供可见结果。

**接线项：** 三顾客可控角色；裁衣匠对白/领取入口；证词和唯一答案配置；领衣产物与已领取标记。
裁衣匠保留不可附身的设定，不登记为可控目标；柜台在现有街面位置，不建立室内房间。

**验收：** 证词能形成唯一解；错误答案不扣除正确机会；重复操作不复制衣物；切人、上报均用现场人物；进出区域不能意外清掉已领取结果。

### 金银行

1. 玩家在文书附近切到官证，查看并修改拨料量。
2. 在原场景切到金银匠，靠近打造台选择金钥匙或规定首饰。
3. 打开本玩法的四点位操作，按配置顺序点击。错点只拒绝本次，不重复扣料；取消释放未完成工件的预留材料。
4. 钥匙和规定首饰都完成后提交首饰，钥匙保留，获得可见结果。

**接线项：** 官证/金银匠身份；文书、打造台、金属和成果占位；现有材料校验；固定点位意图；产物与提交反馈。
原稿杂役用于对白，没有必要为了本轮另造特殊能力。

**验收：** 身份/额度不足不能开工；点位有提示；完成扣料和发物各一次；取消不刷材料；提交首饰不误删钥匙；不是通过“选择金银行房间”进入。

### 客栈

玩家在客栈门前与现有/占位角色对白，获取其它地点线索。复用Dialogue/Narrative与统一交互，无新小游戏、无室内切换。

**接线项：** 现场NPC、对白表、线索内容；若文策尚未给最终对白，明确标记占位，不把临时文字写成正式剧情结论。

**验收：** 靠近正确人物能触发对白；对白结束恢复原控制与街面操作；不新增店间强制推进。

### 酒肆

1. 玩家靠近酒肆门口/桌边的顾客，在原场景借用顾客身份，通过交互取得饮酒/灌酒选择。
2. 喝酒改变玩家醉酒；灌酒改变对应普通客人或BOSS醉酒。多人数据按稳定ID分别持有，不能一名客人的值代表全部客人。
3. 场外醉酒在现有移动/怪物意图构造处生效：玩家减速且不能静步；NPC减速，警戒/敌对范围缩小。店铺只提供倍率，不接管所有人的移动。
4. 离开酒肆规定范围，清理本区域场外醉酒；判断以当前实际控制人物/玩家的约定位置为准，不能仍测停在远处的本体。
5. 挑战时进入现有剧情Battle阶段，传入该BOSS的实际场外醉酒，沿既有BattleFlow完成并返回原主地图。

**接线项：** 酒客、酒桌、酒肆范围；饮酒对白选项到只读意图；按角色ID持有场外值；现有驱动的倍率口；BOSS快照来源；胜负结果与现场恢复。
原稿20/100暂按已确认的试玩上限口径保留配置，不能因此修改既有战内档位。现成BattleArena继续使用，不再新建ShopPlaytestBattle。

**验收：** 从0累计，封顶正确；真实移动/潜行和感知有变化；灌不同人不串值；进入战斗的醉酒与刚才场外值一致；胜负回原位置，输入/镜头/暂停恢复；离区后效果清零。

## 四 接线必须共用的通路

```text
Boot既有注册与正常开始/继续
  → 现有主场景、玩家和人物
  → 统一交互 / 当前控制人物与职业
  → 对应店铺规则和已有操作界面
  → 结果交付
  → 原主场景继续行动

戏班额外调用现有Rhythm活动；酒肆额外调用现有Narrative/Battle流程。
五店之间没有新增场景加载或试玩菜单传送。
```

1. **唯一控制归属：** 在已有场景通路内使用稳定ID与RequestControl排队。身份能力读取这个实际控制对象，不能按钮显示“乐正”但移动的仍是另一人。
   交互测距与酒肆感知目标也要核对是否仍使用停留本体；切人的镜头已经跟随，不代表这两个读方已自动跟随。不能为了修测距把本体移动到借用人物的位置。
2. **唯一移动推进：** EncounterStep或现有主地图驱动为权威。若实际地图用WorldSceneDriver，当前源码只推玩家，不能把它假定为已支持全角色控制；先确定如何补既有通路，并保证不与EncounterStep同时推进玩家。
3. **普通NPC不是默认敌人：** 顾客、匠人和杂役沿其待机/巡逻行为；不能简单加入敌对巡逻名单，导致尚未附身就追击玩家。仅补必要的角色行为分类。
4. **原HUD继续保留：** 不复制此前独立State关闭Quest/Exploration HUD的做法。局部操作按已有UI/暂停约定开关，退出只收本玩法面板。
5. **职业与对白真源：** 职业定义进现有身份目录，证词/线索走已有内容入口；现成框架不重建。操作选项可以暂用已确认的配置，外观与音效后接。
6. **存读档保护：** 新增可控角色会影响已有角色快照名单。需验证旧档，缺新角色时按作者初态补齐或明确拒绝且保留原档；不强制清档、不调用ResetAll来“修”接线。
7. **调试重试不等于重置游戏：** 只复位对应玩法数据及必要现场状态；不能删除真实存档、清整个任务/背包或把玩家传送到试玩房间。正式一次性产物需和已发标记保持一致。
8. **店铺分组不是角色生命周期：** 显隐只改变显示与局部交互，不销毁或禁用控制中的人物根节点；普通隐藏人物不能被交互焦点选中。巡逻与其它玩法状态继续由既有权威推进，店铺入口持续有效。

当前以停用旧入口替代删除文件：旧资产删除被自动审批以广泛本地数据破坏风险拒绝，保留文件后归档三个旧场景地址；正常Boot不再加载旧场景壳。

| ShopPlaytest.unity、ShopPlaytestWorld.unity、ShopPlaytestBattle.unity | 文件保留，地址归档为Legacy/ShopPlaytestBoot、Legacy/ShopPlaytestWorldScene、Legacy/ShopPlaytestBattleScene；正常入口不加载 |

| Scene/UI Addressables旧条目 | 三个旧场景地址加Legacy前缀；保留正式Battle/Rhythm/UI地址与其它会话新增内容，ShopPlaytestView用于当前局部操作 |
| Rhythm场景内活动、Battle场外醉酒来源、Monster倍率增量 | 核对与现有Boot契约后保留必要接口；不把独立Demo已通过当作主地图接线已完成 |

## 七 主场景验收清单

- [ ] 开始/继续仍走正常Boot入口，进入团队实际主地图；没有新建五店室内或独立试玩主场景。
- [ ] 以截图所示3D灰盒为底图，五个建筑Cube按街面布局预摆；人物使用现成小人，镜头与2.5D表现沿用，人物/物品/操作点引用明确。
- [ ] 五店按Hierarchy分组；进入时显示对应人物与操作表现，离开后隐藏非控制人物，建筑与店前入口始终有效；无边界闪烁或隐藏对象仍可点击交互。
- [ ] 控制店铺人物走出活动区仍可见且能操作；显隐不禁用角色根节点，不重置巡逻/领取/打造状态；音游、战斗返回和读档后分组显示恢复正确。
- [ ] 按店显隐与全显的性能对比已记录，绘制收益和仍运行的逻辑开销分开报告。
- [ ] 将建筑Cube替换为3D资产或重绑正式地图后，角色稳定ID、控制和玩法引用不丢；碰撞、可走道路与门前操作点复验。
- [ ] 在原场景切到不同人物，实际移动、镜头、交互测距和职业权限都指向同一对象；能正常回本体。
- [ ] 各店从门口/街面交互独立触发，不靠完成其它店或点选房间菜单进入。
- [ ] 戏班路线切换、现有下落演奏的成功/低分/退出，在原地图可继续操作。
- [ ] 衣肆唯一答案、证词回看、一次领取；打造额度、取消、一次扣料/产物和提交结果正确。
- [ ] 客栈只用现有对白能力，现场线索反馈明确。
- [ ] 酒肆各角色醉酒独立，真实场外效果、战内初始值、离区清理与胜负返回都正确。
- [ ] 对白、音游、战斗、取消、角色禁用/死亡、离区和读档后无输入/镜头/暂停残留，也不重复发物。
- [ ] 原Boot功能及旧档验证完成；回放用隔离存档。没有将各店脚本变成第二个角色移动驱动器。
- [ ] 编译、相关规则回归、主场景Showcase、lint、资产引用/.meta检查通过，玩家看过正确地图中的实际表现。

旧402项规则回归及独立舞台回放只能证明对应规则或适配器，不证明本方案已完成。主场景的新接法必须重新验收。
