# 钩子提示与阻断的写法

> 这几条的出处：一套 75 技能 / 21 钩子的成熟 harness 的**翻车记录**，
> 加上本工程自己踩到的两次。机制怎么搭见 `../hooks/README.md` 与
> [harness-authoring.md](harness-authoring.md)，这份只管**说什么、什么时候说、拦不拦**。

## 1. 注入文案写第三人称事实陈述，不写祈使句

官方文档明示：钩子注入的祈使句会触发模型的 prompt-injection 防御，
整段被当可疑内容 surface 给用户，而不是被当上下文吸收——祈使写得越硬，越不生效。

| 正例（陈述事实 + 可选的下一步） | 反例（祈使 / 只说被拦了） |
| --- | --- |
| `<文件> 的必读文档在本会话没有读取记录：…… 读过之后本次编辑即可放行` | `改 <文件> 之前你必须先读：……` |
| `本会话已连续 5 次编辑 <文件>，中间没有改过别的文件。常见的出路：……` | `停下来！你在反复试错，请立即换一条思路` |

尺子：把提示读成一条**状态描述**还通顺，就合格；读起来像在命令人，就改。

## 2. 只在写操作上注入，读操作放行

`Edit` / `Write` / `MultiEdit` / `Bash` 这类会改东西的调用才值得注入提示；
`Read` / `Grep` / `Glob` 一律静默。读操作是高频的，每次都塞几行提示，
一轮下来上下文里全是同样的话——那是 context rot 的燃料，不是护栏。

## 3. 同会话同提示只注入一次，key 是**提示文本**

`_hook_common.should_emit(session_id, text, tag)`（JS 侧是 `guard.js` 里的
`shouldEmitOnce`，共用同一份账本 `.claude/.cache/emitted-<会话>.txt`）。

按文本哈希去重，不按文件名：同一个文件的**另一条**提示（规则集变了、模块 guide 刚生成）
该说；同一条提示换个文件名不该重说。本工程按文件名去重时两头都错过。

**deny / ask 不去重**：那是决策不是提示，去重掉的那一次就是护栏漏掉的那一次。

## 4. 单条精简——多个钩子会拼接，这是常驻税

同一事件上注册的钩子并行跑、输出拼在一起。每条都写三行，三个钩子就是九行，
每次编辑都来一遍。一条提示只回答三件事：**哪个文件 / 为什么 / 下一步有哪些**。
背景、原理、示例往 `ai-docs/` 和规则文件里放，别塞进注入文案。

## 5. 阻断要克制：只有解锁链路可靠时才 deny

**强制机制的成本不在「拦不拦得住」，在「解锁链路可不可靠」。**

参考 harness 的「改代码前先读文档」闸原本是 exit 2 硬拦，最后被迫降级成软提示。
根因不是判据错，是解锁依赖埋点落盘：子 agent 读的、跨会话读的、记录没落盘的，
统统解不开锁。模型读了文档也过不去，工具反复被拒就进入「换个写法再试」的自主重试循环。

本工程踩的是同一个坑：`required-reads.py` 早先只认 `Read` 工具的记账，
主窗口用 Bash `cat` 读完模块 guide 再编辑，照样被拒。修法是**把解锁链路补成
一条人和模型都能确定打出来的命令**（现在 `cat` / `head` / `tail` / `sed -n` 也记账），
而不是把闸降级。

所以：

- **解锁靠状态推断 → 一律做成提示**，别 deny。状态推断总有断链的那天，
  而断链时的表现是「按提示做了也过不去」，那是最坏的一种故障。
- **解锁靠一条确定命令 → 才可以 deny**，并且 deny 文案里必须写清那条命令。
- 拦截与提示的**识别效果相同**：8 个子代理的对照实验里，无提示组 0/2 发现问题，
  advisory 组 3/3 点名并停手。活性成分是「提示 + 自查引导」，不是阻断本身。

本工程目前只有 `required-reads.py` 的缺必读、和 `guard.js` 的生成物 / 签名 / 派单
这几条硬不变量在 deny，别再加第三类。

## 6. 成功静默，失败冗余

无事发生**零输出**（`project-lint` 已经是这样，照抄）。要说话时说全：
哪个文件、为什么、下一步怎么做。只说「被拦了」的提示会让人去拆护栏而不是照做。

## 7. 每个钩子必须能被单独测试

改完能立刻验证的钩子才敢改；验不了的钩子最后没人敢动，只能整个删掉。

- 判据写成**纯函数**（`doom-loop-detect.bump()` / `should_warn()`、
  `required-reads._bash_read_targets()`），别把逻辑埋进 `main()` 里的 if。
- 测试放 `.claude/hooks/tests/`，L1 测纯函数、L2 用子进程喂真实 stdin JSON 断言退出码与输出。
- 一条命令全跑：`python .claude/hooks/tests/run.py`。`/gc` 会跑它，钩子坏了会被发现。
- 加了新提示或新判据 → 补一条测试，没有测试的判据等于没加。

## 检查清单

- [ ] 注入文案是第三人称陈述，没有祈使句，写清了下一步。
- [ ] 只在写操作上注入；读操作静默。
- [ ] 提示走 `should_emit` / `shouldEmitOnce` 去重；deny / ask 没有被去重。
- [ ] 单条 ≤ 4 行；背景已下沉到规则或 `ai-docs/`。
- [ ] 新增的 deny 有一条确定命令能解锁，且写在了拒绝理由里；否则改成提示。
- [ ] 无事发生时零输出；异常时 fail-open（`required-reads.py` 的 deny 除外）。
- [ ] 判据是纯函数，`.claude/hooks/tests/` 里有对应用例，`run.py` 全绿。
