# harness 自身的编写规则

> 这套规则来自一个 75 技能 / 21 钩子的成熟 harness 的**失败清单**，不是设想。
> 他们 18 个钩子里最后只剩 1 个还在硬拦，聚合器建成后从没被消费，
> 一套 900 万 token 的评估跑了三轮、第一轮的问题七周后被原样再抓一遍。
> 共同死因只有一个：**机制没有载体**。

## 载体锚定（缺一不上线）

新增任何「会自己跑起来」的东西——钩子、定时任务、周期性扫描、生成物刷新、
自动同步——必须在文件头注释里写明三项：

| 项 | 要求 | 反例 |
| --- | --- | --- |
| **执行载体** | 什么机制会真的触发它。必须锚定一个**已被证明在运转**的机制：钩子事件、用户会主动敲的命令、CI 触发 | 「每周跑一次」——谁来跑？日历不是载体 |
| **状态锚点** | 一条 5 秒内可证伪的检查，让人立刻判断它还活着没有 | 「运行正常」——怎么验？ |
| **退场条件** | 什么情况下**删掉它**，而不是加更多提醒 | 不写，于是烂在那儿没人敢动 |

给不出载体的，显式标 `NO-CARRIER(预期停摆)`，不要假装它会被「记得来做」。
标了就是诚实的 fire-and-forget，不标而指望自觉才是问题。

**已证明在运转的载体（本工程）**：PreToolUse / PostToolUse / Stop / PreCompact 四个钩子事件、
`/gc`、`/unity-test`、`/review-change`、GitHub Actions 的 push 与 tag 触发。
**未证明的**：任何需要人「想起来」的周期性动作。

## 不建伴生跟踪文件

不新建「待办清单」「健康快照」「组件注册表」这类**需要人维护才准确**的文件。
清单本身无载体维护，必然腐烂，而腐烂的清单比没有清单更坏——它让人以为自己有全局视图。

需要全局视图时**现扫一遍**。本工程全量重扫是秒级的，重扫比维护基线便宜。
`/gc` 就是这个原则的实现：不存快照、不设周期、人发起时全量扫。

## 资产归哪一层

新增一样东西前先判断，放错层等于加载不到：

```
1. 在改进 harness 自身吗？        → 进化层  .claude/skills/evolution/ · /learn · /gc
2. 定义多步流程 / 工作流吗？      → 编排层  .claude/commands/ · PRP 四阶段
3. 是约束 / 禁令 / 强制检查吗？   → 策略层  CLAUDE.md 硬规则 · .claude/rules/ · hooks/ · project-lint
4. 提供参考信息 / 经验 / 记忆？   → 知识层  ai-docs/ · 模块三件套 · pitfalls.md · memory
5. 是具体工具 / 能力 / 集成？     → 能力层  .claude/skills/ · MCP · scripts/
```

横跨多层的按**主要职责**归主层，在别层写一行引用。

## 三类资产别混

- **Rules**（`.claude/rules/`）说「**不要做什么**」——约束，按 glob 自动注入，150 行以内。
- **Docs**（`ai-docs/`）说「**这是什么**」——知识，按需读，可以长。
- **Skills / Commands**说「**怎么做**」——流程与模板。

规则不是文档。规则写长了会稀释注意力，实测会让最核心那条的遵守率**下降**。
细节往 `ai-docs/` 沉，规则只留「必须 / 禁止 + 一个精简示例」。

## CLAUDE.md 是入口不是全书

它每次会话都全量加载，是最贵的常驻上下文。参考经验：塞到 300 行后，
后加的规则遵守率明显下降（业界观察是模型能可靠遵循的指令在 150～200 条量级，
配额被「介绍性内容」占掉，真正的约束就挤不进去）。

**只放**：硬规则、目录约定、路由表、入口表。
**不放**：架构介绍、模块列表、任何「知道了有好处但不影响判断」的信息。
写不下就下沉到 `.claude/rules/`（按 glob 注入）或 `ai-docs/`（按需读），
在 CLAUDE.md 留一行指针。

## 同一约束只放一处

把同一条约束同时写进规则、文档和 PRP 模板，不叫双重保障，叫噪音。
双重保障的前提是**职责互补**：

- **lint 能机械检出的** → 只进 `project-lint/rules.json`，不再写进规则正文
- **lint 查不到、要读上下文推理的** → 进 `ai-docs/pitfalls.md` 或规则，并在 lint 那侧不重复

`pitfalls.md` 里的条目若被升级成了 lint 规则，正文只留「关联：lint 规则 `<id>`」，不留全文。

## 检查清单

- [ ] 新增的自动化写明了载体、锚点、退场条件（或显式标 `NO-CARRIER`）。
- [ ] 没有新建需要人维护的清单 / 快照文件。
- [ ] 资产放在正确的层，命名与该层约定一致。
- [ ] 规则文件 150 行以内；细节已下沉到 `ai-docs/`。
- [ ] CLAUDE.md 没有因此变长（新增内容进了规则或文档，只留指针）。
- [ ] 这条约束没有在别处重复存在。
