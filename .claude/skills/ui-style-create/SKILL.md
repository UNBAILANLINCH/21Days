# 按项目风格创作新 UI

现有 ui-beautify 解决给定参考的置入，不能代替无设计稿时的样式选择与布局决策；本技能只补这一段，实施与验证复用它，不另建 UI 框架。

## 输入与证据

接受：界面用途、所属模块／已有入口、数据来源、必要状态、特殊约束。允许只给用途，其余先从工程查明。按项目约定读取目标模块 guide；追踪现有 View、调用方、预制体、编辑器生成器、输入动作与测试。列出实际数据和状态，确认哪些由哪个服务提供。玩法规则或关键交互若仍无定义，集中问具体缺口，同时继续无歧义的风格工作。

读取 [风格参考](../../../ai-docs/docs/ui-style-reference.md)，实际打开其中与本界面最相近的两类成品截图、对应原 PNG，并读取目标预制体参数。参考中的“实测／推导／未确认”不能互换；现有交付瑕疵和临时占位不升级成规范。若文件已变化，以当前资产及实读为准，窄幅更新这份参考。

## 创作与落地

1. 先优化操作与信息层级，再选择构图。以玩家当前要做的决定为主：依次发生的操作按步骤呈现，结果先给结论，把计算过程／解释放在可展开详情；有新线索要有可发现入口，不能删掉业务信息。检查首次使用者是否看得出下一步、返回是否保留选择、结算后焦点是否落在可用按钮。减少文字靠分层与渐进展示，不靠缩小字号。改呈现不等于改规则；同时出拳不能擅改成后手看前手。
2. 按业务阅读顺序选择列表查阅、操作台、现场 HUD 或低频反馈的构图。写一张简短对应表：信息／动作、真实来源、选用组件／切片、状态。说明尺寸和字阶哪些复用、哪些是本次设计；不把任务叠页或打造阵盘硬套所有界面。
3. 优先直接引用参考表中的空白底板、按钮、结纹和分隔；保留透明度与装饰比例。烘焙了其它店名、卦象、数量或业务语义的图不当通用素材。只在确实缺少装饰时使用 imagegen；生成图只做无字装饰，不能替代 TMP、控件或业务接线。
4. 完整读取 [ui-beautify](../ui-beautify/SKILL.md)，复用其资源归档、TMP/UGUI、Canvas、安全区、事件刷新、恰好三版动效与验证流程。动态文字必须可编辑，宋体／黑体及真实字重分开，Heavy／SemiBold 的 Bold 近似明确说明。生成器保持同一风格，或拒绝覆盖已交付美术。
5. 沿现有 UIView／UIService 和业务入口接入；没有入口的原型明确标记为原型。保留暂停、输入、返回、中断、结果、存档和数据校验；不因美术增加计时、奖励或新玩法。动效采用推荐的一版，另两版仅文字，复用 LitMotion 和原根过渡。
6. 用目标界面实际走一遍技能：正常、交互、结果／空态／拒绝等真实状态；至少基准、低分辨率、宽屏预览；同尺度并排比较两类既有 UI，确认字阶、色彩、装饰密度和选择反馈。回放与静态夹具分别报告。检查实际入口、键鼠／手柄、重复开关、动画中断和暂停恢复，执行相应 lint、编译、测试及 gc_scan。

## 交付

交付真实界面／预制体、可视预览、资源与样式对应、三版动效和采用项、实际验证结果与近似。记录写入现有模块／批次文档并挂 catalog；风格事实只维护在上面的参考，不复制第二套 tokens 或运行时风格服务。遵守共享编辑器串行约定，不自动提交推送。

调用示例：

> `$ui-style-create 为酒肆现有 TavernFingerGuessView 制作行酒令界面，沿用 ShopPlaytestState 的出指、喊数、醉意与结果；保留离席及再来一拳。`

> `$ui-style-create 为 <模块> 的 <用途> 创建界面；入口 <现有类或无>，数据 <服务／接口>，状态 <实际需要的状态>。`

首个实作及验证见 [行酒令记录](../../../ai-docs/docs/ui-tavern-20261020.md)。
