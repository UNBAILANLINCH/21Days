> 状态：设计草案，供评审；未实现、未完成运行验证。
> 日期：2026-09-22。
> 本次产物：实现方案、开发阶段及验收标准。架构确认后再拆文件级 tasks.md；本文不代表已批准代码实现。
> 新建理由：现有框架文档描述通用服务，没有覆盖剧情与对白、操作、战斗交替及统一恢复的契约。本文件保留跨模块设计决策，不替代现有服务文档。

## 1. 目标与边界

玩家能够阅读带立绘的对白、逐句推进、选择分支、查看交谈历史、快进已读对白和存读档；剧情中可以交还操作、等待交互、进入战斗，并根据玩法结果继续。

剧情不是从头播到尾的台词列表，也不按固定时间自动走完。剧情阶段可以长期等待玩家行为；战斗继续由战斗模块运行。本文的“节点”表示可保存的流程位置，不表示战斗回合，也不要求整个剧情按固定 tick 步进。

首版必须覆盖：

- 对白打字、补全文、下一句、角色名、左右／中间立绘、表情切换。
- 选项分支、实际交谈历史、仅已读快进。
- 阻塞对白与可移动旁白；剧情等待地点、交互及战斗结果。
- 手动槽位存读档；对白、探索等待、战斗中的一致恢复。
- 内容检查、纯逻辑测试与可观看验证场景。

首版不包含：可视化剧情编辑器、任意脚本执行语言、历史点击回滚、语音口型、Live2D、自动播放、云存档、存档缩略图。全屏演出可在后续复用剧情阶段契约接入，本期不实现演出编辑系统。

## 2. 已确认基础与实际缺口

| 现有能力 | 复用方式 | 尚需实现 |
| --- | --- | --- |
| uGUI、TMP、IUIService、UIView | 对白、历史及存读档窗口；分层、安全区、生命周期 | 对白专用 View 和资源 |
| IAssetService／Addressables | 加载立绘、对白预制体 | 角色表情映射、加载取消和释放 |

| Luban／IConfigService | 强类型剧情内容 | 剧情、对白、选项及角色表 |
| VContainer、MessagePipe | 注册模块、传递玩法结果 | 剧情阶段和实例关联协议 |
| IGameFlow／SceneGameState | 大粒度玩法状态和场景切换 | 剧情接续、玩法恢复接线 |
| ISaveService／JsonSaveService | 槽位 JSON、分区版本迁移 | 一致快照、恢复协调、内容校验、独立已读档案 |
| SimulationRunner／EncounterStep | 固定 tick 的战斗逻辑 | 输入阻断、终局结果与恢复入口 |

源码事实：

1. `JsonSaveService.LoadAsync` 成功后替换存档分区实例；模块不能缓存旧分区继续使用。
2. 现有 Load 的反序列化失败保护不等于整个游戏恢复事务；它不验证剧情 ID，也不恢复场景／运行时 Model。
3. `MonsterEncounterState.OnSceneReadyAsync` 调用 `EncounterStep.Begin`，后者重置玩家和怪物；该路径不能直接用于恢复进行中的战斗。
4. 当前检查的 Monster 公共接口及上述入口没有完整的、带战斗实例 ID 的剧情终局返回协议，需要补齐。
5. 现有回放接口可供核对状态完整性，但回放二进制格式不能未经版本与字段审查就直接充当长期存档格式。

## 3. 架构与职责

```text
Narrative：当前剧情阶段、等待条件、分支与恢复协调
    ├─ Dialogue：播放一段对白，返回选项／结束结果
    ├─ 探索／交互：开放操作，报告地点或交互完成
    └─ Monster：启动或恢复战斗，报告战斗结果

上述 Runtime 模块 → Core 的 UI／资源／输入／存档／状态流服务
Core 不引用 Narrative 或 Dialogue
```

拟新增两个模块，仍归现有 Game.Runtime，不为每个类添加接口或独立程序集：

| 模块／组件 | 职责 |
| --- | --- |
| NarrativeModel／NarrativeRules | 纯数据与纯 C# 阶段迁移；校验结果是否属于当前等待 |
| NarrativeController | 启动／恢复阶段、管理订阅与取消、调用玩法公共入口 |
| DialogueModel／DialogueRules | 台词位置、选择校验、已读判断、历史追加规则 |
| DialogueController | 资源、输入、打字、快进与 View 生命周期 |
| DialogueView／DialogueHistoryView | 展示当前状态并提交操作，不自行推进剧情或改玩法数值 |
| NarrativeSaveData／DialogueSaveData | 纯 DTO，分别保存剧情位置及对白阅读状态 |
| GameSessionController | Runtime 层统一协调存读档与各模块 Capture／Restore，不自行实现文件存储 |
| 各模块 Installer | 复用 GameplayInstaller 注册方式 |

具体类的合并以实现时职责为准。既有模块仅扩展实际需要的公共入口；不新增通用节点解释器、反射命令系统或插件注册框架。

IGameFlow 只负责探索／战斗等大状态；每句话不注册成 GameState。Narrative 生命周期跨越这些状态，切场景不会意外销毁剧情进度。

## 4. 内容数据与身份

### 4.1 数据来源

剧情内容沿用 `Tables/` 的 Excel → Luban；生成代码和数据由现有工具生成。展示参数使用 DialogueConfig：字体、字速、立绘布局、动画时长和快进间隔。运行时不修改配置资产。

| 表 | 最小字段 |
| --- | --- |
| 剧情阶段 | StoryId、StageId、Kind、PayloadId、按结果区分的后继 StageId |
| 对白节点 | ConversationId、NodeId、Revision、Kind、SpeakerId、Text、NextNodeId |
| 立绘变化 | NodeId、Slot、Action（保持／显示／清除）、CharacterId、ExpressionId |
| 选项 | NodeId、ChoiceId、Text、TargetNodeId；需要时增加明确类型的条件／结果字段 |
| 角色表情 | CharacterId、DisplayName、DefaultExpressionId、ExpressionId、SpriteKey |

剧情阶段首版只需 Dialogue、WaitInteraction、Battle、End。地点到达作为交互完成的一种来源；按具体用例增加类型，不建立任意字符串表达式语言。

对白节点首版只需 Line、Choice、End。选项条件由规则计算；选项结果通过所属模块公开入口应用，不在按钮里修改背包、任务或好感度。

### 4.2 身份规则

- 所有已发布 StoryId／StageId／NodeId／ChoiceId 稳定且不可复用，禁止用表格行号作为存档位置。
- 内容修订号和 DTO 结构 Version 是两件事：前者判断内容兼容、已读失效，后者负责数据迁移。
- 每次进入剧情阶段生成持久化 ActivationId；战斗另外具有 EncounterId。结果必须匹配当前激活实例。
- 重复结果不重复推进；有意重新进入同一阶段会产生新 ActivationId。
- 读档重建运行时 SessionGeneration，不沿用旧异步回调的代次。仅持久化 ID 匹配仍不足以屏蔽读档前的迟到回调。

## 5. 剧情执行与玩法衔接

### 5.1 标准流程

```text
遇见守卫（对白）
  → 开放移动，等待城门交互
  → 守卫阻拦（对白及选择）
  → 开始城门战斗，等待本次 EncounterId 的结果
      ├─ 胜利 → 放行对白 → 开放探索
      └─ 失败 → 被捕对白 → 牢房探索
```

进入阶段前先写入当前阶段与激活身份，再建立监听，然后发起对应动作，避免动作同步完成时漏掉结果。等待条件必须有可查询的当前状态；加载时先订阅再核对状态，不能只靠将来可能不会再发出的单次事件。

首版一条主剧情同时只有一个活动阶段。阶段可长期等待，不设置任意超时来自动判成功。取消、返回主菜单和错误都是独立结果，不当作胜利或正常结束。

阶段内的 UniTask 只用于本次运行；保存显式 Model，禁止依赖 async 调用栈恢复剧情。

### 5.2 战斗契约

扩展现有战斗模块，提供语义明确的开始、恢复、结束结果：

- 开始：根据 EncounterId 和配置初始化新战斗，允许 Reset。
- 恢复：装载场景并恢复存档 Model，禁止走 Reset 覆盖快照。
- 结果：Victory／Defeat／Aborted，与 EncounterId、ActivationId 关联；同一战斗仅结算一次。
- 结算与剧情迁移之间禁止保存半状态；已结算标志、奖励状态和后继剧情位置进入同一快照。

战斗继续使用 SimulationRunner；剧情不自己每帧算伤害或读取表现 Transform 判断胜负。向叙事层通知结果应在本 tick 状态提交后处理，避免在遍历战斗逻辑中直接切场景。

### 5.3 输入与暂停

分别定义“玩家能否操作”和“世界是否模拟”，不可用一个 Time.timeScale 开关替代：

| 场合 | 玩家操作 | 世界模拟 | 对白表现 |
| --- | --- | --- | --- |
| 阻塞剧情对白 | 阻断移动、攻击、交互 | 暂停相关玩法逻辑 | 正常 |
| 行走旁白 | 保留移动等操作 | 正常 | 正常 |
| 历史／存读档窗口 | 阻断下层输入 | 暂停相关玩法逻辑 | 暂停推进 |
| 战斗阶段 | 战斗输入 | 正常 | 可按内容需求显示非阻塞旁白 |

现有固定 tick 模拟不依赖 timeScale 暂停，因此必须在玩法入口阻断意图／暂停相应步骤。优先用会话层集中计算权限，关闭上层窗口后重算，而不是无条件 EnableMap，避免绕过仍在生效的另一层限制。

输入走 Input System。UI 的确认不能同时触发移动交互；同一输入帧只消费一次。影响玩法的选择结果通过明确意图应用，若要求录制回放，该意图及剧情状态也必须纳入回放，不能宣称接了 UI 就自然支持回放。

## 6. 对白展示行为

### 6.1 推进与打字

状态：Preparing → Typing → AwaitAdvance／AwaitChoice → 下一节点或 Completed。

- Typing 时确认只补全文；下一次独立确认才推进。
- AwaitChoice 时普通推进无效，只接受当前节点的有效 ChoiceId。
- Preparing、恢复、关闭期间拒绝推进；快速连击不得跨过多个未显示节点。
- 一次设置全文，通过 TMP 可见字符控制显示；不每帧 Substring，不把富文本标签算作字数。中文字形、富文本及组合字符实际效果纳入验证。
- 表现使用不受世界暂停影响的时间。取消上一节点的打字、立绘动画、资源等待后才能更新下一节点；异步完成还要核对当前会话代次。
- 关闭／取消必须释放句柄与订阅。取消不返回“对白成功完成”。

### 6.2 立绘

Model 保存左／中／右槽位的角色、表情、是否显示及当前说话者。没有变化指令时保持，Clear 才移除；支持一人独白、双人对白和旁白无说话者。

CharacterId＋ExpressionId 解析资源；缺表情回退角色默认表情并记录诊断，连默认图也缺失时隐藏该槽位且给出开发错误，不阻塞所有输入。资源错误不可误记为剧情已完成。

资源只持有当前需要的句柄；替换成功后释放旧句柄，失败时不得将旧图错当成新表情。淡入、淡出、说话者高亮由 View 完成，不参与剧情逻辑。

### 6.3 选项

显示时计算可选项，点击时重新校验当前状态与条件；提交后立即阻止重复点击。全部选项不可选且没有配置出口时进入可诊断错误状态，不静默死等。

首版旁白不弹交互选项；进入 Choice 时切换为阻塞交互，并在结束后按当前剧情策略恢复权限。

## 7. 历史记录与已读快进

历史是玩家数据，与调试 Log／Telemetry 分开。每条保存访问序号、节点身份、当时角色名、变量替换后的实际正文或已选择选项文本。全文显示完成时追加一次；同一节点第二次实际访问可以再次出现，不能全局按 NodeId 去重。

历史窗口只阅读，不回滚；打开时暂停推进并退出快进，关闭后由玩家重新开启快进。历史跟随槽位恢复，不保留该槽位存档时点之后的交谈。首版默认保留最近 500 条，作为可调整的产品默认；UI 分页展示，旧条目截断需明确提示。

快进规则：

1. 默认仅已读；进入节点前用 ConversationId＋NodeId＋Revision 判断，完整显示后再标记。
2. 每次仍走正常规则，不能直接跳到末尾，必需结果不得跳过。
3. 遇未读、选择、操作等待、战斗、窗口遮挡或错误停止。
4. 每帧限制处理数；无等待的环路由内容校验报错，运行时仍有推进上限保护。
5. 不恢复读档前的快进开关，读档后默认关闭。

已读集合首版作为玩家独立档案跨槽位持久化，不随读旧档回退；历史和剧情进度仍属于槽位。当前 ISaveService 的全部分区会一起写盘／替换，不能只新增一个普通分区假装实现独立档案。

开发时为 Core/Save 增加最小的独立档案存储能力，Core 不含对白字段，Runtime 定义已读 DTO；复用现有 JSON 和安全写盘做法，只抽取实际重复的部分。档案写入合并到对白结束／正常退出等时机，不逐字写盘。档案损坏时备份损坏文件并退回“未读”，不影响剧情槽位加载。

## 8. 存档与读档

### 8.1 保存边界与内容

存档捕获在主线程的一致边界执行：暂停相关模拟和输入，等待当前规则／选择／结算提交完成，再复制所有模块 DTO；之后允许后台写盘。所有手动保存、读档和档案写入按目标串行，防止共享临时文件冲突。

| 分区 | 保存内容 |
| --- | --- |
| Narrative | 剧情／阶段 ID、ActivationId、等待目标、战斗关联、内容版本、已提交状态 |
| Dialogue | 当前节点、当前访问身份、阶段、已解析正文、立绘槽位、历史与当前句是否已记录 |
| 玩家／战斗／探索 | 各模块拥有的状态：生命、位置、场景、敌人状态、AI 所需计时、结算标记等 |
| 随机与模拟 | 需要继续同一战况的逻辑随机流及必要的时钟状态；由所属模块提供 |

字段完整性必须逐项核对现有 Model，不把上表当成已穷尽的战斗快照。各模块 Capture／Restore 对自己的数据负责；对白不复制战斗字段。

打字中可以存档，恢复后本句全文显示并进入 AwaitAdvance；如原快照尚未记历史，恢复时只追加一次。选择前保存则恢复未选择界面。存档不保存任务、订阅、动画句柄、Unity 对象或剩余打字时间。

场景加载、结算应用等短暂不稳定区间，保存请求等待稳定边界；取消／错误要明确返回，不能无限排队。战斗中保存是本期验收项，不能以只支持战前存档替代。

### 8.2 读档事务

现有 Load 直接替换分区，不能满足“内容或场景恢复失败时原游戏仍可继续”。需最小扩展为候选读取与显式提交；保留原调用兼容性，避免 Core 引用玩法校验器。

过程：

1. 冻结当前会话操作，关闭快进；保留旧 Model 快照及恢复所需资源，不提前销毁唯一可恢复现场。
2. 读取候选档，完成格式／分区版本迁移；候选阶段不修改当前分区。
3. Runtime 校验剧情 ID、场景、节点类型、选择、内容兼容及模块快照；解析并预备所需资源。
4. 在暂停状态恢复场景和各模块，再恢复剧情等待与对白画面。恢复入口不触发新开局奖励，也不重新 Begin 战斗。
5. 全部成功后提交候选存档和新会话；重新 Get 分区、释放旧现场、恢复权限。
6. 任一步失败回滚旧 Model／场景并提示原因，禁止覆盖原槽位。回滚也失败时保留磁盘档并返回可恢复的错误界面，不伪称原现场无损。

需要在实现时检查 IGameFlow／SceneGameState 的销毁顺序，使旧场景保留或可重建的策略成立；不能仅增加 try/catch 就宣称事务完成。

内容变更策略：稳定 ID 仍存在且语义兼容可恢复；删除／改义的节点必须提供显式映射或判不兼容。整套配置 hash 变化只作为诊断线索，不一律判坏档，也不静默跳到故事开头。遇高于代码支持的必要分区版本应拒绝加载，不能沿用当前实现的警告后默认读取策略。

### 8.3 槽位界面

首版提供固定数量手动槽位（默认 10）、保存时间、剧情位置、保存／读取／覆盖确认。数量是配置默认，不是已确定的产品要求。

槽位摘要必须通过只读读取获得，不能调用 LoadAsync 来刷新列表。保存失败保留旧档并提示；取消与写盘失败区分处理。现有 WriteAtomic 在部分文件系统退化为 Copy，该退路不是严格原子替换；实现阶段需补备份恢复及失败测试，不能沿用“所有平台断电绝对安全”的表述。

## 9. 开发过程与阶段出口

以下为架构级实施顺序，不是文件级派工清单；设计确认后再生成 tasks.md。每阶段只扩展需要的能力，不提前搭空框架。

| 阶段 | 工作与依赖 | 可交付结果／出口 |
| --- | --- | --- |
| P0 契约核对 | 读取涉及模块三件套与 Model；核对暂停、场景生命周期、回放、存档字段；固定一段端到端测试剧情 | 开始／恢复／结束边界、DTO 字段清单明确；不会把现成战斗误当可恢复战斗 |
| P1 内容与对白闭环 | 表结构、稳定 ID、内容检查；纯规则后接 UIView、TMP 和立绘 | 连续台词、补全文、换表情、结束均可操作；旧回调不能串句 |
| P2 选择与阅读功能 | 分支校验、历史、已读档案、快进 | 双击选择不重复；快进不越过未读和选项；历史文本准确 |
| P3 剧情衔接 | Narrative 阶段；地点／交互结果；战斗关联与胜负；权限和暂停 | 白话 → 操作 → 白话 → 战斗 → 结果对白跑通，错误／取消不冒充完成 |
| P4 一致存读档 | 各模块 Capture／Restore；候选加载、校验、提交／回滚；槽位 UI；并发与安全写盘 | 台词／选择／操作等待／战斗中均可恢复；不重发奖励、不重开战斗 |
| P5 验证交付 | EditMode、PlayMode、Showcase、内容检查及模块文档 | 下述验收矩阵全部有证据；用户观看验证场景后做视觉验收 |

P1 就使用最终稳定 ID 与可存档 Model；不能等 P4 才把所有进度从 View 字段搬出来。P3 的玩法接口和 P4 的战斗恢复属于完成范围，不能以演示用假事件替代最终接线。

预计触及：`Runtime/Dialogue/`、`Runtime/Narrative/`、实际需要扩展的 Monster／Player 等模块、`Core/Save/`、`Tables/`、UI 预制体及立绘资源、Tests 和模块文档。新资产由 Unity 创建并生成 meta；本 spec 不创建这些目录或资产。

## 10. 验收矩阵

| ID | 必须满足的行为 | 验证方式 | 阶段 |
| --- | --- | --- | --- |
| A01 | 正在打字时确认只补全文，下一次才推进；富文本正确 | 规则测试＋Showcase | P1 |
| A02 | 左右角色换表情、突出说话者；缺图不串图；取消后无迟到覆盖 | PlayMode＋Showcase | P1 |
| A03 | 分支按 ChoiceId 进入正确目标，双击只应用一次结果 | EditMode＋Showcase | P2 |
| A04 | 历史保存实际文本和所选选项；重复访问可重复记录，恢复不重复 | EditMode＋Showcase | P2、P4 |
| A05 | 已读可快进，未读／选择／玩法等待停止；内容修订视为未读 | EditMode＋Showcase | P2、P3 |
| A06 | 读旧槽位不清除跨槽位已读；档案损坏不破坏剧情槽位 | 存储测试 | P2、P4 |
| A07 | 阻塞对白禁止操作并暂停相应模拟，旁白允许移动；窗口嵌套不误解锁 | PlayMode＋Showcase | P3 |
| A08 | 剧情等待真实交互／战斗结果；错误实例、重复事件、读档前回调无效 | EditMode＋集成验证 | P3、P4 |
| A09 | 胜利／失败进入不同剧情；中止不结算胜利 | 集成验证＋Showcase | P3 |
| A10 | 打字中／选择前／交互等待时恢复正确；无副作用重放 | EditMode＋集成验证 | P4 |
| A11 | 战斗中恢复生命、位置、AI 状态与必要随机状态，继续后结果一致 | 固定输入恢复对照测试 | P4 |
| A12 | 结算及分支切换边界存档不重复发奖励、不丢结果 | 边界测试 | P4 |
| A13 | 损坏档、未知节点、高版本及资源恢复失败不覆盖旧槽位；回滚有验证 | 故障注入测试 | P4 |
| A14 | 连续保存／读取不发生共享临时文件竞争；列表预览不加载游戏 | 存储与集成测试 | P4 |
| A15 | Windows 与 Android 布局安全区、触控确认／选项／历史可用 | 编辑器与真机记录，未测明确标注 | P5 |
| A16 | 内容重复 ID、失效跳转、缺资源、无出口选择和无等待环路被发现 | 内容检查器 | P1、P5 |

Showcase 至少分三条：对白与阅读、操作与战斗衔接、存读档恢复；每条控制在项目规范的 3～10 步。逻辑断言优先放 EditMode，资源、UI、取消和真实场景接线放 PlayMode。测试复用项目现有框架，不另加测试依赖。

## 11. 风险与默认决策

- 初版仅一个活动主剧情，不做多条并发剧情调度；普通任务系统未来独立接入。
- 仅已读快进、500 条历史、10 个手动槽位为本 spec 的默认选择，可在实现前调整，不是用户已经确认的数值。
- 战斗保存范围是最大的实现风险，必须先核对实际状态字段和暂停边界，缺字段不能以“加载成功”作为通过。
- 跨槽位已读和候选读档都是现有 Core/Save 的实际能力缺口，需要通用、最小扩展；先补对应测试再接 UI。
- 模块规范中仍有“Input System 尚未落地”的旧说明；当前源码已有输入服务，实施以实际源码契约为准，不照抄过时判断。
- 本次只交付 spec；未运行 Unity 编译、游戏测试或真机测试，所有验收项当前均待实现和验证。
