## 一、这一天做出了什么

**对话系统 `Game.Dialogue`**，分两期，都按 PRP 四阶段走（[`PRP/dialogue-system/`](../../PRP/dialogue-system/)）。
协作者先前提交了对白规则与设计稿（`d5a9d12` 及两版设计文档），本轮在其上把它做成能玩的整条链路：
- 一期：按编号拉起对白、世界时停、打字机、左右两槽立绘、条件选项、三连点补全 / 倍速 / 自动 / 跳过、历史面板、Luban 内容表。
- 二期（参考明日方舟 SideStory 四张截图）：范围交互焦点与右下角「对话」按钮、NPC 头顶「…/!」标记与名字、
  跳过先弹确认、选项改右侧竖排胶囊加图标、无对话树 NPC 的头顶常驻台词气泡。

**Core 两处小补**：`IWorldPauseService`（世界暂停）与 `FallbackCamera`（Boot 相机让位）。

**拼接小人 `Game.CharacterPuppet`**：Q 版角色的待机 / 走路，5 张可染色分件 + Animator，替换 SampleScene 里玩家与巡逻者的纸片。

## 二、关键取舍与理由

| 取舍 | 当时的理由 | 后来发生了什么 |
| --- | --- | --- |
| 立绘收成**左右两槽** | 既有代码是左 / 中 / 右三槽；参考画面是立绘在对话框左上 / 右上、说话者一侧亮，两槽就够 | 保持。`DialogueContent.SlotCount = 2`，旧的 `slotCount` 配置删了 |
| 点击节奏、倍速、自动计时拆成**纯 C# 策略类** `DialoguePlaybackPolicy` | 放进规则类会让规则依赖表现时间；放进 Controller 又依赖 UI / TMP、做不了 EditMode 测试 | 保持。时间由调用方传入，三连点窗口、倍速循环都有测试钉住 |
| 世界暂停收口到 Core 的 `IWorldPauseService` | `Time.timeScale` 是全局单值，对话、暂停菜单各改各的会互相覆盖；原方案只停逻辑 tick、不停 timeScale，还要调用方记得接 | 保持。多持有者引用计数，最后一个释放时恢复**进来前**的值而不是置 1；表现层一律读 unscaled 时间 |
| 内容表用 Luban **JSON**，一文件一棵树 | 对话树是嵌套结构，在 Excel 里难维护；schema 用 XML 定义，将来切回 Excel 只改 `input` | 保持。代价是 JSON 不许缺字段，见第五节 |
| 广播用 **C# `event`**，不用 MessagePipe | `GameplayInstaller.Install` 拿不到根作用域的 `MessagePipeOptions`，再注册一套会冲突 | 保持。载荷仍是 `readonly struct`，将来能拿到 options 再换 |
| 跳过**先弹确认**，确认后本段不可撤销，停在选项 | 一期是一键跳过，误触代价太大；停在选项是因为选择影响剧情，不能替玩家选 | 保持 |
| 删掉「已读快进」开关，保留已读记录 | 新需求是一键跳整段，与读没读过无关；记录留给将来「只许跳已读」或已读标色 | 保持 |
| 焦点系统直接读 `Gameplay.Confirm` 动作 | 工程约定玩法只读确定性输入源；但「触发一段对话」不进逻辑帧、不影响回放 | 保持，行尾 `lint-ok` 注明是例外，**不是先例** |
| 常驻气泡**不暂停世界、不开面板** | 路人闲话不该打断探索；与对话树完全两条链路 | 保持。台词暂放 Inspector `bubbleLines` |
| Boot 相机让位做成 Core 小组件 | Boot 相机 depth 0 在玩法相机之上重画，玩家看到灰底、点击射线却走玩法相机——HEAD 本来就如此，不是本轮引入；`SceneGameState` 不知道相机，`GameBootstrap` 只管启动 | 保持。只靠场景加载 / 卸载事件，不轮询；「回标题恢复」当时未实测 |
| 小人**不引入 Spine / Live2D / 2D Animation 包** | 用户要的是「简单即可、看运动表现」；新包带来授权、导入管线与美术工具链成本 | 保持。驱动层只依赖 `Moving` / `Speed` 与根 `localScale.x`，将来换 Spine 只换表现层 |
| 小人按 **0.1 s 窗口**攒位移再判走 / 停 | 逻辑 tick 60 Hz 可能慢于渲染帧，单帧位移时有时无，逐帧判会走路时闪回待机 | 保持，起步 / 停步阈值另做滞回 |
| 小人 Animator 走 **UnscaledTime** | PRP 初稿写的是「对话时停时动画定格」，实看定格像卡死 | **方案改了**：时停期间待机呼吸照播，驱动层在 scaled 帧长 ≤ 0 时强制切回待机 |
| 原纸片**隐藏不删**，做 `flipX` 载体 | `EncounterSceneView` 往纸片上写 sprite 与朝向；改它要动协作者的模块 | 保持，`EncounterSceneView` 一行未改 |

## 三、刻意没做的（别重新提议）

| 没做 | 为什么 | 什么情况下再议 |
| --- | --- | --- |
| 遭遇自动触发、剧情推进、选项结果驱动玩法 | 归 Narrative，协作者那条线还没收口 | Narrative 接线时，按 [`follow-up-integration.md`](../../PRP/narrative-dialogue/follow-up-integration.md) 第 4、6 节 |
| 对话存读档、已读记录持久化 | `Capture / Restore` 与存档形状已有且有测试，但存档 UI 与槽位不归本模块 | 同上 |
| 非阻塞旁白 | 字段与规则都留着，本期所有对白一律时停等点击 | 真有边走边说的内容时 |
| 常驻台词进表、本地化 | 只有一个村民两句话，进表的收益不够 | 路人台词成批出现或开始做本地化时 |
| 对话框手绘边框、贴纸、背景模糊 | 等美术给图，预制体已按「只换 Sprite」留好层级 | 美术出图时 |
| 小人真骨骼形变、攻击 / 受击动画、换装 | 本期只验证运动表现 | 定下战斗表现方案时，优先看 Spine |

## 四、与协作者并行开发

同一天协作者在同一工作区做 narrative、quest、2.5D 探索场景，编辑器与未提交文件是共用的。当时的处理：
- **未提交文件按内容判归属**，不按文件名：字体资产、URP / QualitySettings、quest 全套都是对方的，一律不碰、不暂存。
  唯一例外是修动态字体图集坏页时对对方未提交的字体资产做过一次 Clear Dynamic Data，当场告知。
- **SampleScene 由对话系统一起提**：场景里既有对方已完成但未落盘的灰盒，又有本轮的三个 NPC，拆不开；
  先按用户决定留着不提，后在 `4a7e385` 连同灰盒一次提交，提交信息写明灰盒属于另一会话。
- MCP 改场景前先读编辑器状态确认对方不在 Play，逐步存盘、只动本轮物体。
- 全量 EditMode 里两条遗留失败（回放格式版本、存档迁移）来自协作者 `d5a9d12`，记录在案、本轮不改。

## 五、踩到的坑（已沉淀进 `pitfalls.md` / 规则 / 技能）

| 坑 | 结论 |
| --- | --- |
| `gen-tables.ps1` 首次下载 Luban 后解压失败 | 本机没有 7-Zip，系统 `tar` 解不了这份 7z；装 7-Zip 或用 `py7zr` 解 |
| Luban JSON 生成报缺字段 | JSON 数据源不许缺省，空串、空数组、`false` 都要写；一个文件放数组要写 `*@文件名` |
| MCP `execute_code` 报「Feature not available in C# 6」 | 本编辑器走 codedom 编译，只认 C# 6；改写法，不重试 |
| 多条 Showcase 都加载 Boot，第二条起叠出多套容器 | `GameBootstrap` 没有重复实例保护；`[UnityTearDown]` 里销毁旧 `GameLifetimeScope`（`DestroyBootScope`） |
| Showcase 验「正在打字」总是红 | 默认 1.5 s 停顿够十几个字打完，检查时状态已过；验瞬态那步写 `hold: 0f` |
