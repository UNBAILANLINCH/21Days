## 3. P0：先让偏差可解释、可复现

### P0-A 统一时间诊断与可回放输入记录

**输出**：带版本的会话诊断记录、纯逻辑回放入口和最小定位报告。记录不接入现有固定 tick ReplayFormat，也不宣称能重现物理出声；先验证记录格式和读取契约，再实现写入。

记录至少包含：session、谱面/音频标识与版本或内容指纹、片段起点、预约 DSP/realtime 起点、被选桥接样本跨度、三种 offset 快照、实际输入更新模式；逐事件保存 lane、Press/Release、稳定序号、原始事件时间、到达批次与映射后歌曲时间；逐批保存当前/上一完成边界、实际封口水位与推进顺序。判定保存目标 ID/头尾时刻、原始/补偿后误差、等级、原因及分数变化；自动 Miss 没有输入时间或输入误差，填空值，不填 0。

诊断按有限容量记录或汇总，避免每帧字符串日志。定期保存成对的当前 realtime/DSP 样本、映射歌曲时间与规则推进时间；桥接残差须标明采样方法和跨度，属于软件测量，不能用事件到达延迟冒充时钟漂移。异常记录覆盖迟到、时钟回退、暂停、音频/输入设备变化、停止和重开；读取器严格检查非有限数、版本与顺序。

**验收**：同一记录离线回放得到相同逐枚结果、分数/连击和迟到诊断；回放使用记录的批次边界而非 DSP 当前时间。0/正/负输入补偿与独立视觉值均有样例；卡顿积压、相同时间戳稳定排序、旧 session、过水位输入均可复现。报告列软件残差 median/P95/max 与环境，先取基线再审阈值，不预写硬件精度达标。

### P0-B 听觉声部确认与可试听改谱闭环

**输出**：按音符 ID 的声部确认表、旧/新目标差异与理由、A/B 短循环试听及试听后采用/拒绝记录；正式谱面修改必须有人工听辨依据。优先检查已有检视的歧义点，不先整体平移 56Tap。

**验收**：明确每个候选对应哪个音乐事件、使用哪一种解码时间域；能听原声、当前目标、候选目标，局部修改前后可对比且可撤销。修改不借玩家 OffsetMs 掩盖谱面错误；校验 ID、轨道、头窗/占用冲突与片段范围，再跑规则和场景回归。未取得听感验收则保留候选，不标“已校准”。

## 5. P2：制谱与可读性

### P2-A 外部制谱候选与 canonical JSON

**输出**：工具/格式取舍记录、最小版本化 canonical JSON 契约与严格转换验证。候选为 osu!mania 4K Tap/Hold 子集，尚未选定工具或批准导入；保留现有 SO 到运行副本路径，明确导入/编辑的唯一真源，避免 JSON 和 SO 同时成为可编辑权威。

**验收**：说明整曲时间到片段时间的转换、音频原点、chart offset、列映射与稳定 ID；0ms 首音符合法，负时间预滚不平移谱面。目标仍编译为秒时间，BPM 只作制谱元数据。当前同轨头窗不重叠/Hold占用约束必须严格校验，不能为导入常见密谱偷偷放宽玩法规则。重复 ID、非法类型/轨道、NaN/Infinity、Tap 非零时长、Hold 非正时长和片段外终点均定位报错。遇到 STOP/DELAY/WARP/SV 等尚不支持的事件必须显式报不支持，不能静默丢失或伪装完整兼容；正常子集与拒绝样例都可复验。

### P2-B 等宽琴道可读性（透视计划已取消）

**输出**：等宽四轨皮肤、判定线/轨道边界、Hold 头尾和完成/早放反馈的对照画面与人工试玩记录；保留可用古风/琴弦元素，不绑定具体乐器或把弦数当键数，不重做透视。

**验收**：上下轨宽一致、音符无远小近大，头部中心落到判定线，Hold 显示长度与时间线性对应；DFJK 映射清楚，Tap/Hold 与按住/可松开状态可辨。不同分辨率下保持四列比例和线性滚动，不遮挡误差反馈；视觉改动不改变判定、三 offset 符号或首音符预滚。当前已增加线性映射和网格尺寸回归源码，尚未执行 Unity 测试；可读性仍须实际试玩确认。
