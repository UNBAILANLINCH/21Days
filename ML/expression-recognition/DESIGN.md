# 捏脸表情识别网络 · 设计

*状态：原型；混入公开集的产物不得随包发布，当前Unity部署候选只用合成数据，另有单人dev研究微调　最后更新：2026-10-04*

## 1·问题

玩家在游戏里拖滑杆捏出一张脸，网络判断「这张脸读起来是哪种表情」，并能说「认不出」。

| 项 | 定义 |
| --- | --- |
| 输入 | 捏脸滑杆值向量 `sliders ∈ R^K`（K 与每根滑杆的范围由绑定配置决定） |
| 输出 | `probs ∈ R^C`：各表情类别的概率（已做温度校准）；`energy`：越大越「不像任何表情」 |
| 类别 | 可配置；默认 7 类基本情绪：中性、高兴、悲伤、惊讶、恐惧、厌恶、愤怒。可另用类别集（§5.1）把标注类合并 / 列为集外类 |
| 部署 | ONNX（opset 15）→ Unity Sentis 2.1.x 客户端离线推理；Sentis 2.1.3 支持 Unity 2022.3.11f1+，ONNX opset 7–15 |
| Python子项目边界 | 不包含Unity侧模块、滑杆UI、捏脸渲染；当前Unity接线另见接入规格§17 |

**本功能尚未进入策划文档**（`docs/design/` 的 features 00–15、product、story 都没有捏脸系统，也没有表情识别），需求来自口头提出；玩法落点待策划定。
**当前接入对象**是 laila 场景的 3D 头模（31个形态键 → 17个非视线控制轴 → 图内51维规范空间 → 5类）。唯一执行入口是 [`接入规格 §17工程进展`](../../PRP/laila-expression-recognition/spec.md#17-当前工程候选接手入口2026-10-04)，再读§16契约与阶段顺序。输入变化即时清旧结果，自动识别最多10次/秒，按钮手动重算；结果只作实验展示，不进关卡判定。旧12维上限分析与下文通用七类设计保留来源，不证明当前模型可分性或人工准确率；59D/6类仅研究候选，没有部署。2026-10-04已完成seed42／80轮51D／59D五类候选微调及后续37图输入诊断，当前在输入、数据与拒识核验后继续评估训练；研究候选未部署。文档优先级及逐轮证据由spec§17统一路由。
游戏侧用法举例 [推断]：要求玩家捏出目标神态 → 看 `probs[目标]` 是否过阈值，`energy` 过阈值时判「认不出」。难度由阈值调，不改网络。

## 2·核心思路：在「规范表情空间」里学，而不是在图像上学

```
公开集图片 ──MediaPipe──► ARKit 表情基 51 维 ──┐
FACS 情绪原型（合成）──AU→表情基映射──────────┼──► 规范表情空间 x ∈ [0,1]^51 ──► 分类网络 ──► probs / energy
玩家滑杆 s ──绑定矩阵（导出时固化进 ONNX）──────┘
```

**规范空间选 ARKit 表情基**（browInnerUp、mouthSmileLeft、jawOpen……共 52 个，去掉 tongueOut 余 51 个）：

- 口径说明：MediaPipe Face Landmarker 的 Tasks API 返回的 52 项里，多出来的是 `_neutral`，没有 `tongueOut`；ARKit 原版 52 项则含 `tongueOut`。两种口径各去掉多出的那一项后，是同一组 51 个名字，实现时按名字对齐，不按下标；
- 它是事实标准的面部绑定参数化，语义与 FACS 动作单元（AU）基本一一对应，捏脸滑杆天然能映射过去；
- MediaPipe Face Landmarker（Apache-2.0）能从单张照片直接回归出这组系数（Grishchenko 等 2023，BlendShapes GHUM），公开集图片因此能变成「参数向量 + 表情标签」；
- 分类网络只认规范空间，**绑定改了不用重训**，重新导出即可（绑定矩阵在导出时固化成 ONNX 的第一层）。

**为什么不走图像**：游戏里只有滑杆值，没有真人照片；把捏好的脸渲染成图再过 CNN，会引入「风格化美术 ↔ 真人照片」的大域差，还多一条渲染管线。在参数空间里识别表情有先例：EMOCA（Danecek 等 CVPR 2022）在重建出的 3D 人脸表情参数上做野外情绪识别，纯几何方法与最好的图像方法相当；ExprGen（Aneja 等 WACV 2018）在风格化角色的绑定参数空间里做表情的感知一致性约束；DeepExpr / FERG-DB（Aneja 等 ACCV 2016）让真人与风格化角色共享表情特征空间。

图像类 SOTA（POSTER++、DDAMFN、APViT 等）只作为背景对照，不在本方案里用。

## 3·数据

### 3.1 三种来源

| 来源 | 作用 | 商用 |
| --- | --- | --- |
| **FACS 情绪原型合成**（`configs/facs.yaml`） | 无数据时能跑通全流程；提供「刻意摆出来的、夸张的」表情先验——恰好贴近捏脸 | 干净 |
| **公开集**（RAF-DB、FER2013、AffectNet、CK+、KDEF 等）经 MediaPipe 抽成 51 维 | 真实表情的分布与多样性 | **全部仅限非商用研究** |
| **金标捏脸集**（`golden/*.json`） | 发布口径的验收集：在滑杆空间里、由人标注 | 自有 |

- 合成器的每种情绪有多个变体，来自两类出处，配置里要逐条注明出自哪一类：
  - **EMFACS 典型原型**（Ekman、Friesen、Hager 2002 的 FACS 资料）：完整的「刻意摆出」组合，例如高兴 = AU6+AU12（杜兴式笑）、惊讶 = AU1+AU2+AU5+AU26、悲伤 = AU1+AU4+AU15；
  - **CK+ 最小判据**（Lucey 等 CVPRW 2010，Table 2）：判为该情绪的最低条件，例如高兴只要 AU12、惊讶为 AU1+2 或 AU5（强度 ≤B）、愤怒要 AU23+AU24、蔑视要 AU14。原表见 REFERENCES.md 附录 A。

  - **CK+ 示例图**（同一篇论文的 Figure 1）：例如张嘴笑 AU6+12+25、张口惊讶 AU1+2+5+25+27。玩家最常捏的就是这类「张嘴」版本，不能缺。

  三类出处不许混在一起、都记在 CK+ 名下。AU 强度按 FACS A–E 档采样，并加左右不对称抖动、低强度干扰 AU 和高斯噪声。
- **干净稀疏样本**：玩家捏脸常常只动一两根滑杆、没有任何噪声。合成器要留一部分样本（约 25%）不加干扰 AU、不加噪声，只保留核心 AU，否则这种「干净脸」反而会落到训练分布之外，被判成「认不出」。
- **按绑定剔除做不出来的变体**（可选，训练时 `--drop-infeasible-variants`，默认关）：有的变体的核心动作在当前绑定下根本够不到（例如 laila 候选绑定没有抿唇控制，愤怒的 CK+ 最小判据 AU23+24 投影后整张脸归零，和中性一模一样）。把这种变体留在训练目标里，等于教网络「一张中性脸有一定概率是愤怒」。判定规则：变体的核心 AU（`aus` + 所选备选；`optional` 不加、`drop_one_of` 不删）按统一强度 0.6 摆出，屏蔽维置零，投影到训练绑定，相对残差 ‖x − x̂‖² / ‖x‖² ≥ 阈值（默认 0.9）就不进训练目标。带 `choose`（多选一）的变体**逐个备选**判断，只剔除做不出来的那个备选：剩下的备选仍等概率抽，变体权重乘保留比例（等价于「原分布里只留做得出来的那部分再归一」）。单位绑定投影无损，不剔除任何变体；某个情绪的变体全被剔除时报错（应在类别集里把它列为集外类）。剔除清单（类别、变体、备选、出处、残差）写进 ckpt、report.md 与导出元数据。
- 公开集里**摆拍**数据（CK+、KDEF、JAFFE）比自然场景数据（FER2013、AffectNet）更接近「刻意捏出来的表情」，原型阶段优先用它们评估。
- FER2013 只有 48×48 灰度图，MediaPipe 检出率和系数质量都差，需要放大后再抽，并在报告里给出检出率。
- 数据授权：公开集训练出的模型一律在导出元数据里标 `commercial_use_allowed: false`。FER2013 更特殊：它不是「持证、限非商用」，而是根本没有官方许可证，图片是从网络搜索抓来的，版权来源不明，风险高于其余几个数据集。上线前必须换成自采数据（真人摆拍 + 签授权）或纯合成数据重训。

### 3.2 真人 → 捏脸的域差处理

| 差异 | 处理 |
| --- | --- |
| 真人静息脸系数不为 0（每个人的「中性」都带一点偏置） | 基线归一化：`x' = clip((x − b) / (1 − b), 0, 1)`，b 取训练集中「中性」类的逐维中位数；捏脸的中性本来就是全 0 |
| 真人表情幅度小，捏脸往往夸张 | 强度缩放增强：`x' = clip(α·x)`，α ~ U(0.8, 2.0) |
| 滑杆够不到的表情基（比如绑定里根本没有「鼻翼皱起」） | **绑定投影**：对每个真人样本解有界非负最小二乘，求能最接近它的滑杆值，再用绑定重建，拿重建结果训练（默认 70% 用投影、30% 用原值）；残差统计单独出一份「绑定覆盖度报告」，反馈给捏脸设计 |
| 眼球朝向（eyeLook* 共 8 维）不是表情线索，真人数据里却和情绪相关（悲伤常低头看下） | 默认屏蔽这 8 维，防止学到伪相关 |
| 左右 | 左右互换增强（L/R 表情基成对交换，标签不变） |
| 捏脸常是混合表情（又惊又喜） | mixup（Zhang 等 ICLR 2018）+ 软标签，按标签分布学习（Geng TKDE 2016）的口径训练；复合表情的心理学依据见 Du、Tao、Martinez PNAS 2014 |

### 3.3 「认不出」的负样本

玩家会捏怪脸（本作题材是妖与画皮，怪脸是常态）。负样本 = 随机滑杆组合（随机稀疏度）+ 拮抗 AU 同时拉满（嘴角上扬又下撇、单眼瞪单眼闭等），去掉与任一类原型过近的样本。用于 Outlier Exposure 训练（§5）和「认不出」阈值标定。

## 4·网络

两种结构，由配置切换，默认 `regionformer`：

**`regionformer`（默认）**：按 FT-Transformer（Gorishniy 等 NeurIPS 2021）的思路，把每个表情基当成一个 token：
`token_i = x_i · w_i + b_i + 区域嵌入(眉/眼/颊/鼻/嘴/下颌) + 侧嵌入(左/右/中)`，左右成对的表情基共享 `w_i`（对称先验）。加一个 CLS token，经过 2 层 pre-LN Transformer（d=48、4 头、FFN×2）后，取 CLS 接分类头。
动机：表情是多个 AU 的**组合**，AU 之间的共现/互斥关系决定语义（ME-GraphAU，Luo 等 IJCAI 2022；SRERL，Li 等 AAAI 2019 用 AU 关系图建模同一件事）。token 间的自注意力相当于学出来的 AU 关系图，区域嵌入则把 FACS 的解剖分区作为结构先验放进去。

**`resmlp`（基线）**：51 → 128 → 2 个残差块（LN-Linear-GELU-Dropout-Linear）→ LN → 分类头。表格数据文献里，调好的 MLP 是强基线，必须留着做对照。

规模都控制在 20 万参数以内，ONNX < 1 MB，单次推理在 CPU 上是微秒级。注意力手写（Linear 出 qkv → Reshape/Transpose → MatMul → Softmax），不用 `nn.MultiheadAttention`，保证导出的算子都在 Sentis 支持清单里。

## 5·训练目标

| 项 | 做法 | 依据 |
| --- | --- | --- |
| 主损失 | 软标签交叉熵 + 标签平滑 0.1 | 公开 FER 数据标注噪声大（SCN，Wang 等 CVPR 2020 的动机） |
| 类别不平衡 | logit adjustment：训练时 `logits + τ·log π` | Menon 等 ICLR 2021（FER2013 的厌恶类只占约 1.5%） |
| 认不出 | Outlier Exposure：对负样本推向均匀分布，权重 λ=0.5 | Hendrycks 等 ICLR 2019 |
| 噪声标签（可选） | 对称交叉熵 SCE 开关 | Wang 等 ICCV 2019 |

优化：AdamW、余弦退火 + 预热、早停看验证集 macro-F1，固定随机种子。

### 5.1 类别集（label set）

标注协议固定在「标注类」上（`configs/labels.yaml`，默认七类），验收可以用更小的「类别集」（`configs/label_sets/*.yaml`，训练时 `--label-set`，不传就是七类）：

| 字段 | 含义 |
| --- | --- |
| `classes` | 输出类，顺序即 probs 顺序；每类有 `key`、`zh`、`from`（由哪些标注类组成） |
| `drop` | 集外类：不进正样本；评估金标时只报告预测去向，不计入任何指标 |

- 每个标注类必须恰好出现一次（某个类的 `from` 或 `drop`），类名不能叫 `unknown`，与标注类同名的类必须包含它自己。
- 合成数据：合并类的样本由成员类平分（每类总数与其他类相同，两个成员各出一半，余数给排在前面的成员），集外类不合成正样本；负样本「离正样本太近」的参照集也只用类别集里的类。
- 公开集 / 金标的标签先经别名归一成标注类，再按 `from` 映射；集外类样本训练时丢弃。
- laila 的验收类别集 `laila_5class`：中性、高兴、悲伤、惊讶/恐惧（surprise + fear）、愤怒；厌恶为集外类（规格 §15.1）。标注者仍按七类加「不明确 / 混合」标，原始标注照原样保存。
- 改类别集（增删、换顺序、改 `from`）必须重训、重导出、重新冻结测试（规格 §11.2），不能只在 UI 隐藏。

## 6·校准与「认不出」判定

1. 温度缩放：在验证集上用 LBFGS 拟合温度 T，最小化 NLL（Guo 等 ICML 2017），并把 T 固化进 ONNX。
2. 能量分数：`energy = −T·logsumexp(logits/T)`（Liu 等 NeurIPS 2020），比最大 softmax 概率更能区分分布外样本。
3. 阈值：按留出负样本（怪脸）95% 被拒（TNR95）取 `energy_threshold`，写进元数据，并报告该阈值下分布内验证集与金标的通过率。游戏侧在 `energy > 阈值` 或 `max(probs) < min_confidence` 时判「认不出」。
   不按「分布内 95% 通过」来定：合成数据的分布内 energy 非常集中，按它定出的阈值会紧贴分布内一侧，把稍有偏离的正常表情误拒（首轮实测：金标里 5 张正确的脸被判「认不出」）。从体验上说，把捏对的脸判成「认不出」，比放过一张怪脸更伤玩家；而且放过的怪脸还要过「目标类概率」这一关。

## 7·评估

| 指标 | 说明 |
| --- | --- |
| accuracy、macro-F1、逐类 P/R/F1、混淆矩阵 | 公开集按官方划分或按人划分，不许同一人跨训练集与测试集 |
| ECE（15 桶），校准前后 | 概率要能直接当难度阈值用，必须校准 |
| OOD AUROC、FPR@95TPR | 分布内验证集 vs 留出的负样本 |
| **金标捏脸集准确率** | 发布口径。公开集上的准确率只说明原型能跑 |

金标集的现状与局限：`golden/sample_rig.json` 目前是按 FACS 原型手写的占位，与合成器同源，**不能证明泛化**。正式的金标集要由多人在游戏内捏脸工具里捏、盲标、取多数票（FERG-DB 的做法），并统计标注一致性。标注者应以本作目标玩家为主：跨文化研究表明，东亚观察者判读表情更依赖眼部区域（Jack 等 PNAS 2012），EMFACS 原型来自西方样本，只是起点。

**最终判定口径**（规格 §7.2、§11.2）：验证集与金标都另报一份按阈值最终判定的指标——混淆矩阵多一列「认不出」、金标多一行 unknown 真值；已知类的判对率、macro-F1、逐类召回都按最终判定算（被拒识计为漏判，召回分母是该类全部样本，精确率分母是被判成该类的全部样本，含 unknown 被误判成它）；已知类被拒识比例、unknown 拒识率单独报。

**金标护栏**（规格 §6.3、§10；检查逻辑在 `exprnet/golden_check.py`，评估、训练、`golden_check` 命令共用）：

| 检查 | 不过时 |
| --- | --- |
| `rig` 等于模型训练绑定名；带 `rig_hash` 时等于训练绑定的完整哈希 | 报错退出；只有显式 `--allow-golden-skip` 才降级为跳过，并在报告里写明 |
| `schema_version` 为 1，`entries` 非空；`id` 非空且不重复 | 报错 |
| `expect` 是标注类、`unknown`，或 unknown 的别名 `ambiguous`（标注协议的「不明确 / 混合」） | 报错（类别集的类名如 `surprise_fear` 不是合法标注） |
| 滑杆 key 在绑定里，值是有限数且在滑杆范围内（拒绝 NaN、Infinity、字符串、布尔） | 报错 |
| 开发集与测试集一起查时：同一 `group` 不跨两个集，`id` 也不跨集（`golden_check`） | 报错 |

训练在开始前就查金标，免得训完才发现绑定不符。金标文件 `status` 为 `human-labeled` 时报告标「人工盲标」，否则标「占位，不能证明泛化」。评估加 `--tag <名字>` 时报告写到 `metrics_<名字>.json` / `report_<名字>.md`，开发集与测试集的评估互不覆盖（规格 §7.1）。

## 8·导出契约（给 Unity 侧）

`artifacts/export/<名字>.onnx` + 同名 `.json`。

| ONNX | 名字 | 形状 |
| --- | --- | --- |
| 输入 | `sliders` | `[batch, K]` float32，原始滑杆值，按元数据里的顺序 |
| 输出 | `probs` | `[batch, C]`，已做温度校准的 softmax |
| 输出 | `energy` | `[batch]` |

图内依次做：滑杆裁剪到范围 → 正/负半轴拆分（Relu）→ 乘绑定矩阵得到规范空间 → 屏蔽维置零 → 分类网络 → 除以 T → softmax / 能量。

元数据 `.json`：`schema_version`、`onnx`（文件名、输入输出形状、**`sha256`**）、`labels`（key、中文名）、`sliders`（key、中文名、min、max、default）、`temperature`、`energy_threshold`、`min_confidence`、规范空间维度顺序、绑定配置哈希、训练数据来源、`commercial_use_allowed`、评估指标摘要。

- `onnx.sha256`：最终写盘的 ONNX 文件字节的 SHA-256（规格 §7.4），防同名模型与 JSON 错配；`exprnet.export.verify_pair` 按它核对一对产物，改一个字节就对不上。
- 类别集模型另有 `label_set` 块：类别集名、各类的 `from`、集外类 `drop`、标注类列表；`labels` 就是类别集里的类。默认七类不写这个块。
- 训练时打开了变体剔除的，另有 `training_variant_filter` 块：阈值、探测强度、绑定与哈希、剔除清单。

导出时自动做三项检查，任何一项不过就判导出失败：onnxruntime 与 PyTorch 在 1000 个随机输入上的最大绝对误差 < 1e-5；图里所有算子都在 Sentis 支持清单里（`configs/sentis_ops.txt`，附出处 URL）；文件 < 1 MB。

没有绑定配置时，输入直接是规范空间 51 维（单位绑定）。

## 9·绑定配置（捏脸滑杆 → 规范空间）

`configs/rigs/*.yaml`，每根滑杆的写法：

```yaml
- key: mouth_corner_L
  zh: 左嘴角
  range: [-1, 1]
  default: 0
  pos: {mouthSmileLeft: 1.0}          # 往正方向拉：左嘴角上扬
  neg: {mouthFrownLeft: 1.0}          # 往负方向拉：左嘴角下撇
```

`sample_rig.yaml` 是示例绑定（约 20 根双极滑杆，眉高、眉角、睁眼、眯眼笑、鼻皱、嘴角、张嘴、嘴宽、上唇、下唇、抿嘴、下巴），只用来跑通流程。文件里的 `live2d` 字段是写示例时参照的命名；Live2D 路线已于 2026-09-28 废弃，这些字段仅作历史参照。
`laila_rig.yaml`（`laila_v1`，12 维）及其审阅记录仅用于旧资产复现。当前模型从接入规格 §16 的 17 维契约开始；候选绑定必须明确标注未确认系数与映射损失，不能称为正式绑定。几何证据、独立人工开发集和锁定测试通过后才冻结正式版本。换绑定新增文件，不改旧记录；绑定大改须重训、重标定、重导出。
