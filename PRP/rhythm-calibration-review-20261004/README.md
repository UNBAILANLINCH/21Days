> 本文保留修复前的只读评估证据，以下“当前代码”指评估时的历史实现。已授权的新玩家流程、接口和实际验证见 [实现记录](implementation-report.md)，不能将候选比较结果当作新流程已通过真人验证。

## 结论

截图不能据此断言玩家或设备有错。当前失败提示确实过于笼统，质量门也只检查单次点击误差的离散程度，没有检查偏移估计随时间是否稳定：稳定偏移加 MAD=33ms 抖动会整轮拒绝，50ms 渐变/分段跳变却可能通过。需要把失败原因、点击波动和偏移稳定性分开，而不是直接放宽 MAD 阈值。

本节点只改 PRP，载入真实已编译 Runtime 估计器做 16 个确定性场景与新会话隔离评估；无 Unity MCP 操作、无 Assets 改动、无存档修改、无软件安装。没有拿到用户该轮原始样本，候选方法仅作可复现工程比较，未部署或完成真人统计验证。

| 失败不写新补偿、旧值保留，但没有显式短补测/建议值确认入口 | `RhythmState.cs:530–540`：StopRound 释放估计器，然后 Ready；统一提示“校准不稳定或样本不足”，未展示匹配/剔除原因与时序分析 |

120 BPM 的周期是 500ms，匹配窗恰为半周期，采样内部的大多数有限点击都有一个邻近目标；“检测到但未匹配”通常包括重复/采样范围之外，不能仅凭窗内匹配断言正确跟拍。整拍错位会映射下一拍，稳定 580ms 可得到 80ms 相位估计；当前方法和分段候选都不能识别整周期歧义，不能宣称测出绝对物理延迟。

## 失败后的现有出口

`RhythmView.Ready:103–118` 重新启用校准、开始、练习及两个滑块；可以重试整轮、直接开始保留旧值、手调再演奏或返回。开始和练习在校准中也可取消并切换，不强制校准成功；没有专门“跳过”文案。手调通过 `RhythmView.cs:323` → `RhythmState.cs:482` 更新内存，`:238` 开始前保存，`:590` 返回时保存。成功估计才走 `:538–546` 覆盖并写盘，保存失败有通知。此前实际 Showcase 已验证无样本保留旧 100ms、再校准接受、正负补偿及标题重入；本节点未重新运行 Unity，也未验用户这次 MAD33 的具体数据。

16 个场景及隔离断言实际 PASS，非 Monte Carlo 成功率或真人体验证明。新估计器实例接受 -80ms，旧实例第二轮全部重复拒绝；当前 StartCalibration 每轮确实新建实例，没有已发现的旧轮污染。

候选先稳健剔除，再把原始32拍按时间分四块，检查每块留存和块中位数跨度，保留原始离散度。比较中采用每块≥4、总≥24、块跨度≤20ms、离散度≤60ms 才提供建议，超过原30门须确认。**这些数字只用于测试候选，不是已验证配置；60ms 不用于扩大自动接受门。** 四块中位数一致不构成统计置信区间，无法排除长期相关偏差，暂不使用 iid 标准误或伪置信度百分比。

## 最小改动边界（待正式实现）

1. 只扩展现估计器返回结果：原始输入/匹配数、重复与窗外分类、离群后有效数、候选偏移、原始/过滤 MAD、带目标索引的时序块与明确 reason；保持当前原始事件时间域，不改 AudioService 或判定规则。适应期独立计数，不能把8拍适应输入计为采样失败。
2. UI 显示固定“采样 18/32 拍；已匹配 14 次”等，而不是拿匹配数充当总进度。结束区别无采样事件、已有事件未匹配、样本不足、时序漂移和估计尚需确认；不归咎玩家或设备。
3. 稳定且低波动保留现有质量要求并增加时序守卫；边缘波动但跨段稳定只显示建议值，用户“试听→应用并保存”后才替换。试听候选不得先改原档案，取消/失败保留原值。不静默保存差估计。
4. 轮中不自动补拍或无限延时。轮后用户可主动选**一次固定8拍短补测**、保留继续、手调或返回；始终显示上限。补测保留本轮候选证据，作为独立验证块，不把缺失时序块用后来数据假装补齐；漂移/跳变不把旧新样本混成一个平均数，需要再适应或完整重测。补测仍不足就结束并保留原值。
5. 实现时只动 RhythmEstimator/State/View 和专用规则/Showcase 测试；不加平台、设备库或强制首次向导。先以确定性16场景和真实按钮取消/确认/保存/重试验证，再用普通玩家独立录入数据评估误拒与误接受，不能用合成测试宣布所有玩家都可自动成功。

当前正式算法、30ms 阈值、播放器和用户补偿均未变；用户不必继续盲重试来为这一调查提供证据。
