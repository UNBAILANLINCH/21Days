# 已授权校准修复与组合音符补验

## 范围与验收

保持三首现有谱、DFJK、Tap/Hold、DSP/Input 时间桥及三个偏移语义。校准提供固定主轮进度和分类结果，候选只在玩家确认后保存，可比较原值/建议并保留退出；一次主动8拍补测有明确上限。组合音符只验证现有跨轨能力，不新增练习UI或冗余类型，不改正式曲目难度。

1. 无输入、未匹配、缺样、稳定但波动、漂移可区分，8+32主轮不因漏拍自动延长。
2. 原补偿在分析、试听、补测及取消中保持，只有明确应用候选才替换/保存。
3. 补测仅一次8拍；相互矛盾或不足的证据不合并成可靠估计，允许保留继续或完整重试。
4. 原值/建议试听经稳定参考音及原输入时间域显示校正误差；不将试听写成物理延迟测量。
5. 组合 Tap、多 Hold、Hold+其他轨 Tap、同时间戳顺序与同轨冲突有纯逻辑及真实输入验证。
6. 隔离存档回放覆盖确认/取消/补测上限/重入，编译和文档真实反映结果，不干扰用户 Play。

## 工程边界

估计器继续保留旧 TryEstimate 契约供历史规则测试，新增带样本分类/时序证据的分析结果用于新 UI；结果是纯 C#。State 管固定轮次、一次补测资格及确认保存，View 只显示与发意图。试听不改校准档案，以原始误差减候选值反馈；重新测量构造新估计器。低 MAD 也须通过时序一致性，高 MAD 仅建议确认，不扩大自动保存门。候选统计门沿用评估的工程试验值，不宣称真人保证。

新增/修改范围：Runtime/Rhythm/RhythmCalibrationEstimator.cs、RhythmCalibrationResult.cs、RhythmState.cs、RhythmView.cs；Tests/EditMode/Rhythm 的专用纯逻辑测试与 Tests/Showcase/Rhythm/RhythmShowcase.cs；PRP 与 Rhythm 三件套/HANDOVER。组合类型复用现枚举，不与另一编辑器工具线程共享 Editor 文件。Unity 当前检查为干净 RhythmDemo、非 Play；操作前继续核对占用。
