## 二、关键取舍

| 取舍 | 理由 |
| --- | --- |
| SampleScene 定位为「功能 demo 示例场景」兼回放舞台 | Addressables 地址 `IsometricEncounter` 指向它是**临时**的，正式内容落地后指向 `Assets/_Project/Scenes/` 下新场景，代码不动只改条目 |
| 正式资源场景一律放 `Assets/_Project/Scenes/` | 与 `Boot.unity` 对齐；`Assets/Scenes/` 是模板目录，原位不动 |
| 推翻旧规则「验证场景不依赖 SampleScene」 | 六个 Verify 场景各复制一套 NPC / Encounter，改一个组件默认值会悄悄影响无关模块的验证场景（坑册有先例）；统一到一份 demo 场景只维护一份 |
| 回放缺的物体优先运行时生成并 `Track()`，其次作为 demo 内容补进场景 | 硬约束是不改变从标题「开始」进 SampleScene 的正常游玩 |
| Taming 选「预挂默认不激活」而非 `AddComponent` | 五个引用都是私有 `SerializeField`，`AddComponent` 当场跑 `Awake` 会空引用 |
| 「记得切焦点」做成框架机制而不是 skill 里一句提示 | 机制大于自觉；同理 `InitTestScene` 残留与测试脚本混入正式资产做成 `invariants.py` 检查而不是文档 |
| `IsometricPlayerController3D` 选删组件而不是搬到 Runtime | 它是硬编码速度的原型控制器，正式移动已由遭遇规则驱动 |
| 共用工作区：另一会话同时在改对白 / 演出模块 | 六笔提交全部用临时索引（`GIT_INDEX_FILE` + `commit-tree` + `update-ref` 带旧值校验）构造，交织文件按 hunk 拆，对方已暂存的文件用 `update-index --cacheinfo` 同步而不 `reset` |
