# ai-shared/evolution — 进化产物归档

harness 自进化过程中产生的、**值得长期保留的过程性产物**归档在这里。

| 子目录 | 放什么 |
| --- | --- |
| `signals/` | 线索与复盘：某次踩坑的根因分析、某条规则为什么改、lint 误报的排查记录、改进提案 |
| `weekly/` | 阶段小结：一段时间内 harness 改了什么、效果如何、哪些坑不再出现了 |

命名建议 `YYYY-MM-DD-<短标题>.md`，一件事一个文件。

## 与其它进化机制的分工

| 产物 | 去哪 | 特点 |
| --- | --- | --- |
| 即时教训（现象 / 根因 / 做法） | `ai-docs/pitfalls.md`（由 `/learn`） | 短、可直接指导下次动作 |
| 可正则检测的违规 | `.claude/skills/project-lint/rules.json`（由 `/learn`） | 程序化，钩子自动拦 |
| 用户偏好 / 项目动态 | 全局记忆 `~/.claude/projects/<本项目>/memory/` | 跨会话，不进仓库 |
| harness 引用完整性 | `/gc`（`.claude/skills/evolution/gc_scan.py`） | 体检，不留文件 |
| 行为回归用例 | `evals/cases/` | 验「整套规则能不能让 AI 一次做对」 |
| **过程性产物**（分析、复盘、提案、小结） | **本目录** | 长，有前因后果，不适合塞进 pitfalls |

判断尺子：**能压成三行放进 pitfalls 的，就别在这里开文件**；需要讲清一整条因果链、或者要留给以后回看「当时是怎么想的」，才写在这里。

> 当前为空架，随项目演进逐步填充。空目录靠 `.gitkeep` 被 git 跟踪。
